# Отчёт P2-5 · 0.19.0

Дата: 30 октября 2026. Реализовано управление собственным персонажем по согласованному плану. Рельеф и immutable сцены P2-3, авторизация и reservation P2-4 сохраняют свои роли.

## Серверная навигация

`internal/planet/pathing` — самостоятельный пакет без HTTP/DB. A* использует 8 соседей, octile heuristic, устойчивый порядок обхода и ограничение числа раскрытых узлов. Диагональ запрещена, если перекрыта хотя бы одна боковая клетка. Маршрут сглаживается только после supercover-проверки каждого сегмента; срезать угол через воду/объект нельзя.

Основа — прежняя walkable-маска с радиусом персонажа и коллизией у основания природных объектов. Hex corners и вода остаются непроходимыми. Браузер выбирает клетку; сервер нормализует допустимую цель к её центру. В непроходимой выбранной клетке будет отказ `target_blocked`, а не телепортация к «ближайшей» подходящей точке.

Есть отдельные причины для недостижимой цели и исчерпания бюджета. Сглаживание и размер промежуточного пути также ограничены; отмена проверяется внутри поиска. География и decor seed от игрока не принимаются.

## Runtime движения

`internal/planet/movement.Hub` содержит по одному циклу на активный сектор. В секторе хранятся только текущие server-owned позиции и пути. После ухода последнего controller цикл останавливается; пустые миры не тикают.

Начальные параметры: скорость 4 единицы/s, шаг 50 ms, отправка состояния примерно каждые 100 ms. При отставании dt ограничен 100 ms, поэтому догоняющего большого скачка не происходит. Скорость считается по евклидовой длине сегмента: диагональное движение не ускоряет персонажа.

Расчёт путей — два worker и очередь 32 задания. На каждый новый запрос повышается path generation и отменяется предыдущий расчёт. Запоздавший результат не применяется к новой цели или заменённой сессии. Бюджет и deadline ограничивают тяжёлый поиск. Частота команд — 10/s с burst 20; дубликаты seq не продвигают персонажа. Клиент не задаёт скорость, текущую позицию или готовый путь.

Actor не обращается к SQL на каждом шаге. Разрешение двигаться имеет короткий срок 2 секунды и обновляется после свежей проверки допуска. Если проверка БД/lease/прав задерживается, actor самостоятельно перестаёт двигаться; при ошибке связь закрывается с возможностью resume. Это дополняет DB fencing, а не подменяет его RAM-флагом.

## Сохранение и восстановление

Минимальные checkpoints добавлены уже здесь, потому что движение без сохранения сделало бы refresh небезопасным. Более полная работа с presence/batching/reconnect остаётся P2-6.

`visits.Checkpoint` проверяет account session, visit, connection epoch, control generation, runtime fence, canonical location и character position_version. Пишется только безопасная позиция из server actor. Все проверки выполняются в одной короткой транзакции с прежним порядком блокировок. Нового pool connection внутри helper нет.

Позиция сохраняется раз в 5 секунд при наличии изменений, при disconnect и при нормальном возврате. Перед takeover другой вкладкой общий per-user gate останавливает старый actor и сохраняет его положение; только затем Activate читает персонажа и повышает epoch. Gate также сериализует периодические сохранения и disconnect, чтобы запоздавший checkpoint не затёр более свежий.

Нормальный `leave` по WS атомарно сохраняет позицию и завершает visit. Cosmic затем освобождает свою reservation. HTTP return остаётся безопасным fallback при недоступном WS. При outage/crash используется последнее подтверждённое сохранение; каждый последний кадр не обещается. Завершение runtime отменяет поиск/движение и завершает сохранение до освобождения lease.

## WebSocket и клиент

Тот же endpoint WS v1 получил `move`, `path.accepted`, `state.delta`, `leave` и `visit.ended`. Пакеты привязаны к визиту/epoch. В move разрешены только целые x_q/y_q цели; неизвестные поля отклоняются. У accepted route есть нормализованные waypoints; дельты содержат authoritative позицию и число оставшихся сегментов. Накопление исходящих movement-снимков ограничено: устаревший снимок заменяется последним.

Новый `features/planet/controller.js` рисует Canvas, кеширует фон текущего сектора, отсекает невидимый декор и сортирует персонажа/объекты по Y опоры. Интерполяция отстаёт от сервера примерно на один сетевой интервал, без экстраполяции за последнюю полученную позицию. Клик преобразуется камерой в мировую клетку. Масштаб и pan не участвуют в серверной физике.

Камера следует за персонажем, доступны wheel zoom, кнопки масштаба, обзор ПКМ, возврат слежения и весь сектор. Линия показывает оставшийся путь. Закрытие окна/выход отменяет загрузки, renderer и WS; поздно декодированный PNG не возвращает controller после закрытой связи. При разрыве остаётся последнее изображение с явным предложением resume/return. Использованы исходные PNG без перерисовки; окончательная анимация ходьбы остаётся P2-8.

Строки RU/EN добавлены в существующие каталоги. [Снимок интерфейса](checks/preview.png).

## Миграция и границы

`schema190.sql` только повышает marker до 5, чтобы старые службы не вмешивались в движущегося персонажа. Сцены остаются generator/format v1; их содержимое не перегенерировано. Новых economic tables, выдачи ресурсов или движения корабля нет. Существующих прав P2-4 достаточно.

Космический tick и AFK-планировщик не участвуют в местном движении. Единственный writer позиций — planet. Глобальная карта, колонии, права, корабли и финансы остаются у cosmic.
