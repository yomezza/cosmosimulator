# Отчёт P2-3 · 0.17.0

Дата: 30 октября 2026. Выполнен этап постоянных локальных сцен из согласованного плана. Это серверная основа для последующей высадки; игровая 2D-сцена пользователю пока не открывается.

## Реализовано

### Один источник географии

`internal/planet/scene` читает сохранённый `PlanetSurface`. Не вызывает генерацию другой планеты: высоты, вода, реки и шестиугольник получены из канонического snapshot. Координаты — прежние 256×256 единиц, q=1/1024. Сохраняется центр сектора для общего texture UV; высота клетки округляется до uint16, вода и проходимость хранятся отдельными флагами.

Опорная сухопутная компонента, размер персонажа, размещение платформы и парные порталы используют **тот же terrain policy v1**, что и cosmic reconciler P2-2. Соседи сохраняют одинаковую world-space точку общей стороны. Не вводится новая независимая карта рек или берегов.

### Природные объекты и свободные проходы

До размещения декора резервируются каноническое место будущей площадки, spawn и пути от опорной области ко всем сухим выходам. Место защищается даже в секторе, где площадки пока нет: последующее разделение территории может выдать модуль без смены леса или перестройки сцены. Если cosmic передаст другие координаты/версию layout, scene loader откажет, а не переместит объект.

Детерминированный SplitMix64 и фиксированный порядок попыток дают устойчивые природные ID, позиции и asset IDs. Лесной и сухой/холодный наборы различаются. Используются ссылки на принятый артпак: старые/молодые деревья, кусты, трава, плоские и крупные камни. Растения/камни — декорации и статические препятствия; добыча, запасы, инвентарь и строительство не добавлялись.

У травы нет коллизии. У дерева блокируется основание, а не вся крона PNG. Основания камней и кустов тоже учитываются. Навигационная маска консервативно расширяет bounding box основания на радиус персонажа и половину диагонали клетки; физический ellipse сохраняется отдельно для последующего renderer/controller. Декор не занимает зарезервированные площадки и коридоры. Маска пригодна для будущего A*, сам контроллер движения относится к P2-5.

### Постоянные данные

`schema170.sql`, исполняемая cosmic runner, добавляет `planet_local_locations`. Один ключ `(surface,sector,revision)` фиксирует выбранную версию генератора; уникальный location ID не позволяет создать второй экземпляр той же сцены. Есть FK на канонический сектор, dimensions=256, source checksum, приватный decor seed, версии генератора/формата/проходимости и контрольная сумма сжатого snapshot.

Snapshot содержит JSON-заголовок с метаданными/объектами и плотные массивы высот/флагов, сжатые zlib в BYTEA. Это одна строка на сцену, не 65 536 SQL-строк на клетки и не файловая JSON-база. Восстановление читает сохранённые объекты, а не запускает текущий декоратор заново. Декодер проверяет размер, checksum, версии, координаты, флаги и известные asset IDs. Для уже выпущенных версий предусмотрен отдельный список читаемых генераторов; неизвестная версия требует явной миграции и не перегенерируется молча.

Repository `internal/planet/scenestore`:

- читает согласованный source и существующую сцену короткой read-only транзакцией;
- рассчитывает новую геометрию без удержания SQL-транзакции и глобальной блокировки;
- при commit берёт shared world lock 784218, проверяет действующий lease/fence и свежие canonical bytes/revision/колонию/layout;
- разрешает конкурентный INSERT через уникальные ключи и возвращает именно сохранённую строку;
- повторно проверяет source, площадки и lease для тёплой сцены;
- отказывается читать устаревший/повреждённый snapshot без его перезаписи.

В ходе конкурентной проверки найден конфликт двух уникальных индексов при одновременном INSERT. Исправление: `ON CONFLICT DO NOTHING` учитывает оба ограничения, после чего authoritative snapshot перечитывается по полному ключу и проверяется. В тесте восемь одновременных repository loads получили один и тот же сохранённый результат.

### Жизненный цикл и очистка

`internal/planet/runtime.Registry` объединяет холодные загрузки одного ключа, ограничивает ёмкость и число параллельных расчётов, удерживает сцену ссылками, отменяет подготовку при stop и выгружает неиспользуемую RAM после idle TTL. Метаданные возвращаются копиями, массивы сцены недоступны внешним писателям. Ошибка загрузки не остаётся вечной отрицательной записью; повтор возможен. У пустых секторов нет отдельных тикающих goroutine.

Все immutable данные зафиксированы до выдачи pin. На eviction нет несохранённых изменений персонажа: персонажей ещё нет. Их checkpoint/connection epoch остаются последующим этапам.

Planet service подключает registry и worker очистки к своему lifecycle. При stop отменяются загрузки, завершается worker, затем освобождается lease и закрывается pool. Cosmic по-прежнему работает независимо и единолично обслуживает глобальную карту, колонии, площадки и экономику.

Для удаления глобальной поверхности добавлен барьер `retiring`. Cosmic фиксирует запрос подготовки; planet закрывает вход, дожидается pin/load и удаляет собственные сцены. Cosmic завершает удаление только после повторного подтверждения на свежем preview. Подробный порядок и права — в [инструкции](README.ru.md).

## Проверки

Проверки выполнялись только в новых одноразовых `_test` базах PostgreSQL 17 и в схемах fixture; после завершения базы удалены. Рабочие игровые данные не менялись.

| Проверка | Результат / свидетельство |
|---|---|
| Детерминизм, round-trip snapshot, защита метаданных, коллизии/проходы, вода и парные порталы | PASS; [адресный прогон](checks/postgres.txt) |
| 8 конкурентных repository loads, повторная загрузка новым repository, поздняя площадка, неизвестная версия, повреждённый snapshot | PASS; там же |
| Изменение source между расчётом и commit, смена fence, запрет старого writer, несовпадение checksum источника | PASS; там же |
| Двухэтапный reset и реальный lifecycle HTTP App с worker очистки | PASS; там же |
| Ограниченная PostgreSQL role | INSERT/DELETE своих scenes разрешены; изменения world/users/колоний/площадок/controls/scene UPDATE и DDL запрещены; там же |
| Выборочные прежние reset/backfill/schema/role контракты | PASS; там же |
| 3 registry-сценария и 3 затронутых конкурентных integration-сценария под `-race` | PASS; [race](checks/race.txt) |
| Два отдельных Linux EXE, готовность схемы 3, SIGTERM, crash/lease takeover, независимость cosmic | PASS; [процессный smoke](checks/process-smoke.txt) |
| `go vet` затронутых серверных пакетов и Windows x64 cross-build обеих команд | PASS |

Один синтетический сухой сектор с 549 объектами занимает **10 268 байт** в сжатом snapshot. Это пример размера, не верхняя граница для всех рельефов и не результат нагрузки с 50 персонажами. Диагностика `test-only failed sector insert` в reset-тесте — ожидаемая инъекция ошибки для проверки rollback.

Полный браузерный прогон локально не повторялся: UI игры не менялся, кроме номера версии. CI сохраняет общие проверки. Нативный Windows SCM в Linux не проверен; выполнена кросс-компиляция. Нагрузочная проверка с реальными персонажами относится к P2-9.
