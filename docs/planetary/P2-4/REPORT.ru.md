# Отчёт P2-4 · 0.18.0

Дата: 30 октября 2026. Реализована авторизованная высадка и основа постоянного персонажа по согласованному плану. Добавлен неподвижный технический обзор сцены, чтобы результат можно было увидеть до внедрения движения. Финальный renderer и игровой цикл не объявляются готовыми.

## Функциональность

- Cosmic выдаёт короткоживущий одноразовый ticket только для исследованной системы, завершённой доступной площадки и конкретного своего свободного корабля у планеты. Наличие роли администратора не подменяет корпоративное `planetary.enter`.
- Проверяются манёвр, очередь маршрута, добыча, активное исследование, перевозка и выполняющаяся AFK-задача. Выбранный ship резервируется без изменения его положения; остальные hull не блокируются.
- Ticket — 32 криптографически случайных байта. В DB только SHA256; TTL 60 секунд, привязка к account session, operation digest, поколению допуска, площадке, кораблю и revision. Повтор потерянного ответа перевыпускает секрет и аннулирует предыдущий. После погашения повтор operation возвращает состояние визита.
- Planet повторяет авторизацию и проверки source/layout/ship под короткой транзакцией. Scene готовится заранее. Character, visit и уникальный handoff use фиксируются атомарно. Проверяется также свежий token hash, чтобы перевыпуск билета во время подготовки не оставлял старый секрет действующим.
- Один персонаж на аккаунт. Resume сохраняет visit/позицию и повышает connection epoch; старый controller не может перезаписать новую сессию даже своим запоздавшим disconnect. Новый runtime восстанавливает сохранённую точку; старый runtime fence не принимается.
- Возврат — идемпотентный cosmic revoke с повышением поколения. Planet завершает собственный visit, затем cosmic освобождает собственную reservation. При outage разрешено освобождение только после истечения/смены runtime lease и fencing допуска. DB-ошибка не означает успешный выход.
- Logout, отзыв корпоративного доступа, отключение площадки и retiring завершают визит. Живое соединение перепроверяет допуск каждые 2 секунды. Независимые workers обходят сохранённые записи ограниченными очередями с checked_at, без голодания последних пользователей.

## Границы кода и данных

| Пакет | Ответственность |
|---|---|
| `planet/access` | Общие read-only правила сессии и допуска; никаких записей кошелька/корабля |
| `planet/transfer` | Cosmic-only controls, tickets, возвраты и освобождение reservation |
| `planet/visits` | Planet-only character, use, visit/epoch и завершение |
| `planetserver` | Минимальный WS v1, свежая проверка, registry pins, lifecycle |
| `server/planet.go` | Same-origin gateway, адрес upstream только из настроек оператора |
| `fleet/reservation.go` | Общая проверка закреплённого корабля для cosmic callers |

`schema180.sql` выполняется только cosmic runner под прежним migration lock. Совместимость повышена до 4. Добавлены controls/handoffs/uses/characters, аддитивные поля единственной строки `planet_visits`, индексы очередей и узкое session lookup view. Старые визиты остаются legacy без фиктивной позиции. Идентификаторы новых HTTP-запросов передаются строками; роль/owner/координаты из браузера не принимаются как полномочия.

Единственность записи соблюдается и при очистке: cosmic не UPDATE-ит visits/characters/uses. Planet не изменяет корабли, экономику, площадки или transfer controls. При очистке отзывается только активная операция данной поверхности: исторический ticket не сбрасывает более позднюю reservation пользователя на другой планете. Это проверено отдельным сценарием под race. Негативные проверки PostgreSQL подтверждают, что отдельный planetary login не может читать password_hash/credits или менять cosmic-owned таблицы.

Порядок операций: cosmic exclusive world lock → user/control; planet shared world lock → lease row → per-user advisory lock. Тяжёлая генерация и сетевое ожидание не выполняются внутри SQL-транзакции. Проверки используют тот же переданный DBTX, без вложенного захвата нового pool connection.

## Защита навигации

Ручные route/explore/rescue/portal, продолжение исследования и admin teleport проверяют reservation. Фоновый маршрут пропускает закреплённый hull, AFK-задача ждёт до возврата. Дополнительный PostgreSQL trigger запрещает изменение star/object/mode/destination/local_target/waypoints закреплённого корабля даже через другой raw-SQL caller. Переименование и выбор другого активного hull разрешены. Reservation не является новым положением корабля и не выдаёт ресурсов/кредитов.

## Протокол и интерфейс

Cosmic API: `POST /api/planet/handoff`, `GET /api/planet/visit`, `POST /api/planet/return`. Старые `planet/action land/leave` закрыты и больше не пишут в visits. Реальный возврат использует единый control flow, в том числе для legacy.

Минимальный WS v1: `hello` с ticket либо resume_visit, затем `welcome`; ошибки имеют безопасный code. Snapshot выдаётся авторизованным `GET /planet/api/v1/scene?visit=...&epoch=...` после проверки текущей сессии/визита/epoch. Он не содержит seed, source checksum, кошельки и скрытую геологию. Ticket никогда не передаётся в query string. Origin проверяется точным allowlist до Upgrade; cookie обязательна. Используется закреплённая библиотека `coder/websocket v1.8.14`, собственного parser нет.

Ограничения текущего этапа: hello 5 секунд, сообщение 4 KiB, не более 4 одновременно готовящихся/закрывающихся соединений на аккаунт и 256 на процесс; один действующий controller определяется DB epoch. Resync ограничен по времени/seq. Неподдерживаемые команды движения отклоняются. Нет бесконечного клиентского reconnect: доступны явные «Продолжить высадку» и «Вернуться в космос».

Браузер открывает отдельное фирменное окно технического обзора. Природные PNG и персонаж подгружаются только для сцены, исходные файлы артпака не перерисованы. Полная карта сектора видна целиком; навигация мышью, зум/камера, качественная анимация и финальный арт будут в последующих этапах. Закрытие окна отменяет клиентские загрузки/WS, но не выдаёт себя за возврат. Обработчики после logout/смены пользовательской сессии не восстанавливают старое содержимое. Строки RU/EN добавлены в существующие каталоги.
