# Отчёт P2-2 · 0.16.0

Выполнена подготовка связанных территорий и посадочных площадок. Это космическая часть второй очереди; локальная симуляция персонажей ещё не реализована.

## Изменения

| Область | Реализация |
|---|---|
| Общая чистая геометрия | internal/planet/terrain: 256×256, канонические Sample/Rivers, консервативная маска воды, эрозия на радиус персонажа, наибольшая dry-component, общая сторона и детерминированный Portal, проверка платформы/spawn |
| Владение и граф | internal/planet/territory: owner type+ID, устойчивый порядок, connected components, split/merge без независимого юридического владельца |
| Фоновая подготовка | internal/colonies/landing_work.go: согласованный snapshot, расчёт вне tx, CAS epochs/revision, batch INSERT и уведомления, повторяемая durable queue |
| Схема | schema160.sql: planet_runtime_controls, planet_landing_sites, составной FK к colony/sector, dirty trigger, backfill, schema version=2 |
| API | PlanetState в read-only repeatable tx: landing sites, состояние подготовки и доступные территории; без локальных coords/seed/чужого private graph |
| Права | planetary.enter в allowlist, UI ролей, read model и старой команде land; colonize не заменяет посещение |
| Reset/shutdown | Новые зависимости в eraseSurface, удаление readiness notifications; worker и simulation останавливаются перед закрытием pool |
| Клиент | Значки, легенда, карточки/переход к модулю связанной территории, RU/EN, уведомление и открытие поверхности |
| Графика | Единственный original PNG посадочного модуля из v2, без перерисовки; lazy загрузка карточкой поверхности |
| Сборки | Два Windows x64 EXE 0.16.0, старые сохранены; соответствующая версия planet проверяет schema=2 |

Не изменялись стоимости и сроки колонизации, перечень взносов/возвратов, мировые часы, владельцы старых колоний или сохранённые материки. Тяжёлый расчёт не добавлен в AdvanceColonies: INSERT colony в текущем tx только ставит durable отметку через trigger.

## Проверки

Адресные pure/Go/PostgreSQL сценарии проверяют сушу/реки/изолированные острова, детерминизм, владельцев, первый/соседний/удалённый сектор, мост между территориями, split, повторный backfill, конкурентное завершение/обработку, права и их отзыв, безопасный reset и совместимость marker.

Отдельно выполнены три race-сценария новых DB-механик и проверки границ пакетов/go vet затронутого кода. Старый reset-visits fixture получил явное planetary.enter: администраторская роль больше не является заменой этому праву при корпоративном посещении.

Браузер: прежние три planet сценария и новый сценарий карточки связанной площадки, актуальных прав, уведомления и RU/EN; плюс существующая проверка графа ES-модулей. Полный UI-набор локально повторно не запускался.

В двух настоящих Linux процессах с временной PostgreSQL проверены фоновая подготовка, отдельный модуль удалённого участка, merge без изменения прежнего ID/coords, работа cosmic при остановленном planet и сохранность после перезапуска. Эта проверка не подменяется ручным вызовом Reconcile.

Дополнительное измерение на сохранённой процедурной модели 200 секторов: построение всех масок и проверка shared-side connectivity заняли около **1,86 s** в текущей среде. Это одно измерение расчёта географии, **не стресс-тест 50 игроков** и не гарантия времени на пользовательском Windows.

Журналы: [PostgreSQL](checks/postgres.txt), [race](checks/race.txt), [браузер](checks/ui.txt), [два процесса](checks/process-smoke.txt), [расчёт 200 секторов](checks/budget.txt). Строка `test-only failed sector insert` в reset-тесте — ожидаемая инъекция ошибки для проверки rollback, не провал прогона.

## Ограничения

- В секторе с несколькими островами используется одна крупнейшая доступная область. Мосты через воду и отдельные посадки на малых островах не добавлены.
- Проходимость дискретная с версией policy=1 и запасом на размеры персонажа. Она может консервативно отклонять очень узкие места; берега/реки остаются исходными.
- Пока нет actor runtime, A*, персонажа, сохраняемой local scene, WebSocket handoff и пеших переходов. Stage=P2-2, gameplay_ready=false.
- Кнопка прежней высадки по-прежнему открывает информационное окно первой очереди. Она учитывает отдельное право посещения, но новый выбор площадки/одноразовый ticket относится к P2-4. Подготовленный модуль не объявляется доступной полноценной 2D-игрой.
- Нативный Windows SCM здесь не запускался: две команды кросс-компилированы, работа реальных процессов проверена на Linux.
- Удаление одного завершённого сектора не добавлено как новая пользовательская механика. Split проверяется чистым графом и контролируемой мутацией fixture; штатный текущий reset работает с поверхностью целиком.

Следующий этап P2-3 использует этот же terrain/Portal для постоянных локальных локаций и декора, сохраняя области платформы и проходов. Источником географии остаётся cosmic snapshot.
