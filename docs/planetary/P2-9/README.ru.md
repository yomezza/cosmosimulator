# P2-9 · испытание двух процессов · 0.23.0

Добавлен воспроизводимый эксперимент: 50 авторизованных клиентов подключаются через настоящий космический gateway к отдельному планетарному исполняемому процессу. Обе службы используют одну временную PostgreSQL-схему. Космический worker продолжает выполнять обычные тики и деятельность ботов.

## Повторить эксперимент

Нужны Linux, Go, PostgreSQL 17 и **своя одноразовая БД с именем, заканчивающимся `_test`**. Доступ к ней задаётся в окружении, без credentials в аргументах команд/отчёте. Эта БД не должна содержать рабочие игровые аккаунты. Тест дополнительно создаёт случайную схему и удаляет её после завершения. Не задавать рабочий `DATABASE_URL` вместо тестового.

```sh
export TEST_DATABASE_URL='postgres://test_owner:URL_ENCODED_PASSWORD@127.0.0.1:5432/planet_load_test?sslmode=disable'
export RUN_PLANET_LOAD=1
export PLANET_LOAD_REPORT=/tmp/planet-load.json
go test ./internal/server/integration -run '^TestPlanetLoad230$' -count=1 -timeout=10m -v
```

Тест сам собирает и запускает два Linux EXE из текущих исходников, выбирает loopback-порты и передаёт им только свою БД/схему. Целевой URL или PID существующего сервера задать нельзя. Принудительно завершается только созданный тестом дочерний planet. После аварии он запускается заново, клиенты восстанавливают визиты.

В GitHub Actions есть отдельный **Planetary process load → Run workflow**. Он использует PostgreSQL service внутри runner и сохраняет JSON в artifact `planetary-load-report`. Нагрузка не добавлена в обычный запуск проверки каждого небольшого изменения.

В профиле эксперимента: по 8 соединений БД на процесс, cosmic tick 2s, planet lease 9s/renew 3s, DB timeout 2s, scene idle TTL 2s. Это настройки теста, **не новые значения по умолчанию игры**. Обычный TTL сцены остаётся 2 минуты, lease — 15/5 секунд.

## Что выполняют клиенты

1. Одновременная высадка 50 пилотов в холодный общий сектор и получение авторизованной геометрии через HTTP.
2. Обычное движение: 50 команд/с; затем короткий burst 250 команд/с со сменой целей.
3. Массовое отключение, выгрузка пустой сцены, одновременное восстановление.
4. Возврат и высадка в пять отдельных секторов, по 10 пилотов; проверка изоляции presence.
5. Возврат в общий сектор, настоящее пешее движение к границе и 50 подтверждённых переходов. Повтор confirm не создаёт вторую запись.
6. Ожидание checkpoint, новое движение и жёсткое завершение planet. Cosmic продолжает обслуживать флот и увеличивать tick.
7. Запуск замены, ожидание нового lease/fence, 50 resume с прежними actor/visit и последними подтверждёнными координатами.
8. Возврат всех пилотов, отсутствие живых визитов/закреплённых кораблей, выгрузка кэша. Проверка географии, кредитов, кораблей игроков, колоний, площадок и проходимости checkpoint.

## Технические метрики

Только с действующей сессией администратора:

- `GET /api/admin/metrics` — процесс cosmic, пул, SQL-вызовы, длительность тика и задержка цикла simulation.
- `GET /planet/api/v1/metrics` через тот же origin — процесс planet, пул/SQL, соединения, акторы/сектора, поиск пути/очередь, tick lag, checkpoints, сцены/выгрузка и транспорт.

Обычный игрок получает 403, без сессии — 401. Отзыв роли действует на следующем запросе. Для ограниченного логина planet дополнительно выдать `SELECT(role)` на `users`; без этого старые права позволяют играть, но metrics отвечает 503. Полный актуальный GRANT — в инструкции P2-10.

Метрики агрегатные, без account IDs, cookie, ticket, SQL-текста/аргументов, seed, кошельков или DSN. Диагностических команд изменения мира здесь нет. Они не открывают debug/pprof или произвольный SQL.

Каждая выборка задержек хранит последние **2048** наблюдения; p50/p95/p99 относятся к этому окну. Count/total/max накопительные с запуска процесса. `sql_calls` считает клиентские Query/Exec, включая транзакционные вызовы, но не внутренние SQL триггеров и не равен числу network round trips. QPS получают разностью счётчика за интервал. Pool `empty_wait_ms` — накопленное ожидание; делить его на длительность измерения без учёта параллелизма как latency одного запроса нельзя.

`json_bytes` — успешно записанные серверные JSON payload без WS/TLS/TCP overhead. `mailbox_coalesced` — намеренная замена устаревшего полного кадра новым, не потерянная игровая операция. После перезапуска счётчики обнуляются; фаза отмечена `runtime_restarted` и не получает выдуманный средний CPU через границу процессов.
