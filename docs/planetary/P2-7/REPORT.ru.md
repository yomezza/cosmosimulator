# Отчёт P2-7 · 0.21.0

Дата: 30 октября 2026. Добавлен подтверждаемый пеший переход между соседними локальными секторами. Добыча, персонажный инвентарь и строительство этим этапом не добавляются. Графика сохраняет промежуточный вид P2-6; текстуры/атласы/анимации относятся к следующему P2-8.

## Поведение в игре

В текущей сцене отображаются янтарные маркеры разрешённых проходов и номера соседних секторов. Клик выбирает ingress как цель обычного серверного маршрута. Можно подойти к проходу кликом по земле. Остановившись в пределах трёх единиц, персонаж получает предложение перехода с номером соседа, владельцем и состоянием подготовки.

Соседняя сцена загружается асинхронно и удерживается pin. Пока она не готова, подтверждение недоступно; «Остаться» и новый клик отменяют подготовку. WS, проверка авторизации, presence и checkpoints продолжают обслуживаться. Без подтверждения сектор не меняется.

После отмены предложение не возникает каждый кадр. Повторно выбрать тот же проход можно явно; уход из его зоны также снимает подавление. При успешном переходе подавляется немедленное обратное предложение. Reload создаёт новый controller и может заново предложить ближайшую границу, но не выполняет переход автоматически.

После подтверждения меняется сцена и камера. Персонаж появляется у парного ingress на правильной стороне. Сохраняются public actor и visit, повышается connection epoch. Чужие клиенты получают уход из исходной сцены и появление в новой. [Снимок после перехода](checks/preview.png).

## География и допуск

Переходы используют сохранённые reciprocal portals immutable scene v1. Сравниваются neighbor IDs, surface/revision и общий world-space проход. Проверяется walkability обеих точек, расстояние до исходного ingress и сохранённый canonical source. Ни новых проходов через воду, ни независимой генерации материков не добавлено.

Новый `access.Sector` разрешает только завершённую личную колонию владельца либо корпоративную колонию владельца/участника с `planetary.enter`, при enabled runtime/current revision. В HTTP scene DTO включаются только разрешённые exits; закрытые/незавершённые соседи не получают действующий маркер. Текущий сектор проверяется в Resolve/Activate, Check, Sweep и сохранении, а destination — до загрузки и повторно в commit. Администратор автоматически права не получает.

Исправлена прежняя связь «текущий сектор всегда равен сектору посадочной площадки». Исходный корабль и модуль остаются отдельным anchor допуска/возврата, а текущая доступная colony следует персонажу. Поэтому можно продолжить визит и вернуться на корабль из сектора, которому не положен второй модуль. Зарезервированное генератором место в таком секторе больше не отображается как реально существующая платформа.

## Атомарность и повторные команды

`visits.Transition` получает только серверную frozen-позицию, source/destination immutable scenes и идентификаторы операции. Генерация/загрузка происходит до SQL, без world lock. Commit использует общий per-user gate и прежний порядок world shared → lease row → user advisory lock. В одной tx повторно проверяются session/control/epoch/fence, source и destination, права и position_version.

Departure coordinates сохраняются в receipt; arrival coordinates/current sector/version — в character, target colony/current sector/new epoch — в visit. Только после commit Hub.Join атомарно заменяет controller в RAM; старый loop/queued path не возвращает его назад. Исходный pin освобождается после переключения, destination становится pin текущего визита. Disconnect/shutdown сохраняют уже актуальный controller, а не захваченный defer-ом при входе старый указатель.

PRIMARY KEY(user,operation) и UNIQUE(user,offer) защищают постоянную дедупликацию. Повтор последнего confirm в той же связи возвращает прежний completion после fresh auth, без повторного перемещения. Старые queued команды предыдущего epoch не двигают персонажа в новой сцене. Reconnect читает DB current location, старый RAM offer не восстанавливается и confirm-очередь не переигрывается.

Отказ прав, истёкший offer или известный конфликт операции оставляют исходную location. Ошибка preload/capacity отменяет предложение и освобождает pin. При неопределённом исходе DB commit связь закрывается, чтобы resume установил подтверждённую location: интерфейс не принимает координаты как доказательство результата. Если commit уже успел завершиться до потери ответа/процесса, восстановится destination.

## Код и схема

Добавлены `access/sector.go`, `visits/transition.go`, `planetserver/transitions.go`. HTTP scene-read вынесен из WS-обработчика в `scene_http.go`. Pure scene получила лёгкий accessor Portals без копирования большого списка декора при проверке границы. Физическая симуляция и расчёт путей остаются прежними пакетами.

`schema210.sql` создаёт planetary-owned `planet_transition_receipts` и повышает marker до 7. Идентификаторы удаляемых surface/sector/visit в receipt — значения, не удерживающие FK; FK пользователя сохраняет принадлежность записи. Сама география, генератор/format v1, декор и кошелёк не изменены. DDL выполняет только cosmic.

Ограниченной роли planet нужны `SELECT,INSERT` на receipts и `SELECT(name)` на companies для названия владельца. Остальные права P2-4/6 сохраняются. [Пошаговое обновление](README.ru.md). Обе versioned Windows x64 сборки и общие SHA256 опубликованы; старые EXE сохранены.

## Следом
