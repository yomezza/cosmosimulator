# План этапов, риски и проверки

Статус P2-0: обследование и документы готовы, реализация не начата. Точные сроки не обещаются до каркаса процесса и первого сквозного handoff. Главные сложности — доступ/состояние визита при двух процессах, проходимая связность, восстановление и постоянные версии географии; не отрисовка одного PNG.

## Последовательность

| Этап | Конкретный результат | Адресные проверки / условие перехода |
|---|---|---|
| P2-0 | Аудит, все десять материалов ТЗ, сохранённый оригинальный пак и оценка графики | Статическая проверка документов/файлов; **остановиться на согласование** |
| P2-1 | cmd/cosmosimulator-planet, config, postgres.Open без seed/DDL, readiness, shutdown, runtime lease, граница migration runner, SCM | Cosmic работает при остановленном planet; planet не меняет world/tick и не создаёт галактику; несовместимая схема → 503; второй runtime не получает lease; отдельный Windows EXE |
| P2-2 | Минимальное pure terrain для dry-connectivity + territory graph, landing tables/worker, dirty marker, backfill, обзор площадок | Первый/соседний/удалённый/merge/split/вода/разные owners; конкурентное завершение без дублей; повтор backfill; безопасный footprint |
| P2-3 | Полный local scene repository, генератор декора, compact snapshot, collision/pathing input, загрузка/выгрузка | Детерминизм, одна и та же граница соседей, реки из snapshot, reserved corridors, old generator version, concurrent load/eviction |
| P2-4 | Авторизованный handoff, reservation закреплённого ship, character/visit, возврат/resume; отдельное planetary.enter и UI | Не прибыл/чужой/свободный/неполный проект → отказ; owner/corporate privilege; одноразовый ticket; пропавший ответ; две вкладки; отзыв; ручная и AFK-навигация не обходят reservation |
| P2-5 | Mouse-only Canvas controller, A*, server movement, collisions, camera, существующие UI/локализация | Меняется только цель; нет ускорения спамом; не проходит сквозь воду/камни; target budget; старый path не применяется; zoom не меняет координаты |
| P2-6 | WS v1, реальные две сессии игроков, presence, snapshot/delta, reconnect, checkpoints | Два игрока видят движение; old epoch закрыт; logout/expired auth; backpressure; crash/lease fencing/DB outage; восстановление безопасной позиции |
| P2-7 | Confirm/cancel перехода и destination preload | Правильная сторона/neighbor, разрешённая граница; cancel; ошибка загрузки оставляет исходный сектор; повтор confirm не дублирует actor |
| P2-8 | Подключение принятого artpack, анимации, вода/декор/landing/FX, lazy и cache | RU/EN и узкий экран, масштабы/опоры/порядок Y, не загружается в космосе, финальное художественное согласование |
| P2-9 | Реальные два процесса + изолированная PostgreSQL, нагрузка, проверка совместимости | Обязательные сценарии ТЗ §50, восстановление схемы/backfill, негативные GRANT-тесты, параллельный cosmic tick, reset barriers |
| P2-10 | Документация, две Windows-сборки с версиями, SHA256, GitHub release | Чистая сборка, рабочий rollout/rollback, отдельные SCM/параметры, проверенные release assets. Старые EXE не удалять |

P2-2 зависит от минимальной канонической проходимости — её pure часть нужно написать **до** выдачи площадок. Это уточнение порядка, не вторая независимая генерация. Полный scene/decor/cache остаётся P2-3. Минимальный WS handshake может понадобиться в P2-4/5; полный live stream и reconnect остаются P2-6. Не создавать видимость законченной сетевой игры на клиентской демке.

## Риски и решения

| Риск | Решение и практическое ограничение |
|---|---|
| Ложное соединение островов | Опорная dry-component и парные проверенные portals; правило консервативное, небольшие изолированные острова не дают отдельную посадку P2 |
| Долгий расчёт блокирует экономику | Dirty marker в tick, расчёт вне tx, короткий commit с claims/revision CAS; не ставить всю генерацию в глобальный lock |
| Лишние модули при двух проектах | Один cosmic reconciler, актуальный граф, UNIQUE colony, processed epoch; merge сохраняет старые объекты |
| Билет использован после полёта корабля | Reservation + свежая проверка выбранного ship; все навигационные входы/планировщики включены в аудит изменения |
| Runtime живёт после потери прав/lease | Control generation + DB fencing, bounded auth recheck; при outage приостанавливать управление |
| Deadlock/исчерпание pool | Один tx/DBTX, согласованный порядок, без сетевого ожидания под блокировками; тест конкурентных reset/entry/checkpoint |
| Удаление поверхности оставляет dangling sessions | Блокировать новые входы, drain/revoke, отказывать при живых визитах, явные FK cleanup; не скрывать активных пользователей ради удаления |
| Перезапуск меняет лес/позицию | Immutable geometry version + seed + checksums, checkpoint; не обещать последний потерянный кадр |
| Art preview принят за финал | Отдельный ART с результатами и доработками; принять preview явно либо дождаться новых кадров |
| Переполнение исходящих WS очередей | Ограниченный buffer, coalescing movement, resync/close медленного клиента |
| Перегрузка DB координатами | RAM simulation, пакетные checkpoints, ни одного SQL на каждый кадр |

## Нагрузочное измерение P2-9

50 авторизованных тестовых клиентов в одном секторе, затем в нескольких. Отдельные фазы: cold load, равномерные moves, burst/смена цели, одновременная высадка, переходы, reconnect storm, массовое отключение/idle eviction, принудительное завершение процесса и восстановление. Параллельно настоящий cosmic tick в том же тестовом DB_SCHEMA.

Фиксировать CPU/RSS/Go heap/goroutines, tick lag p50/p95/p99, A* latency и rejected budget, bytes/s и queue drops, время cold/warm sector load, checkpoint latency, SQL QPS/pool wait, задержку cosmic tick. Выходной отчёт содержит среду и длительность каждой фазы, фактические ошибки/потери, число акторов/визитов до и после. Никаких заявлений «держит 50» до результатов. Не запускать это против рабочих аккаунтов или рабочей схемы.

## Проверки именно P2-0

Прочитаны актуальные исходники/схемы/документы и всё полученное ТЗ. Проверены состав ZIP, декодирование PNG, размеры/альфа, совпадение atlas crops с 56 frames, наличие manifest paths, сравнение ground PNG с текущими, края грунта/воды и визуальные previews. Сохранён независимый JSON результата. Содержимое source scripts не исполнялось, demo не подключалось к игре.

Go/UI/race/нагрузочные тесты и миграции не запускались; новые серверные процессы не создавались. Проверка ссылок/изменённых путей документации — достаточна для этого подготовительного изменения. Требуемые будущие автоматические сценарии распределены по этапам, а не запускаются бессмысленно после каждой правки документа.

## Следующее согласование

Утвердить либо поправить архитектуру из README: владельца площадок, conservative connectivity, reservation выбранного ship, схему handoff/возврата, migration runner и статус preview-графики. После этого выполнить P2-1 с отдельным кратким отчётом. Следующие этапы остаются последовательными и не считаются выполненными из-за наличия этого плана.
