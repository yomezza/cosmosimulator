# Планетарный режим: P2-0 — обследование и проектирование

Статус: **подготовительный этап выполнен и согласован пользователем командой «делай»**. Текущий результат: [выполненный P2-2](../P2-2/REPORT.ru.md); [предыдущий P2-1](../P2-1/REPORT.ru.md). Исходный код проверен на commit `68b59558a08653469499480be460a2077c6789bb` (0.14.4). Дата: 30 октября 2026.

В этой работе изменены только документы и сохранён предоставленный артпак. Рабочий Go/JS/CSS, SQL-миграции, игровая БД и Windows-сборки не изменялись. Новая служба и 2D-игра **ещё не реализованы**. Тесты игры и нагрузочные испытания не запускались: это проектирование, а не выпуск новой версии.

## Результат обследования

Первая очередь пригодна как основа: есть постоянная география, секторные идентификаторы, завершённые колонии, корпоративные роли, общий PostgreSQL-пакет и отдельные игровые подсистемы. Новый сервер можно добавить без копирования космического приложения.

При этом нынешняя «высадка» — запись в `planet_visits` и информационное окно, без персонажа и сетевой симуляции. Нет связанных территорий, посадочных площадок, отдельного `planetary.enter`, межсервисного билета, координат персонажа или WebSocket. Эти части требуется разработать. Космический глобальный lock нельзя брать на каждом шаге персонажа.

Графика закрывает почти все категории технического прототипа. Атлас существует, но пакет сам обозначен как preview: диагональные ракурсы и циклы ходьбы требуют художественной доработки. Не объявляем его полностью финальным комплектом. Точные результаты проверки и задания дизайнеру — в разделе графики.

## Основные решения, предлагаемые к утверждению

1. Космическая служба единолично управляет колониями, связанностью территории и созданием площадок. Новый runtime управляет локальными сценами, персонажами и соединениями.
2. Тяжёлый расчёт размещения выполняется вне глобального тика; тик помечает поверхность для устойчивой повторяемой обработки. Существующая площадка не переносится при объединении владений.
3. Связность учитывает сушу, размеры персонажа и возможность пройти внутри сектора. Декор не может разорвать зарезервированные соединения. Личные и корпоративные владения остаются разными.
4. Высадка — на конкретную площадку с одноразовым билетом; новый визит начинается рядом с ней. Переподключение продолжает прежний визит, а пеший переход появляется у границы.
5. При активном визите закреплённый корабль не отправляется в полёт из другой вкладки/AFK-планировщика. Другими кораблями можно пользоваться. Возврат не перемещает корабль.
6. Локальная география использует существующий snapshot; единая версионируемая маска воды и рек нужна и для ходьбы, и для размещения площадок. Новые материки не генерируются.
7. Обновление общей схемы выполняет только существующий космический migration runner. Планетарный процесс проверяет совместимость и подключается без bootstrap/DDL.
8. Для разработки можно использовать графический preview v2. Для окончательного визуального приёма нужны доработки из ART; существующие качественные PNG сохраняются.
