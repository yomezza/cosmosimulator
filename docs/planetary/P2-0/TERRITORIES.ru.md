# Связанные территории и посадочные площадки

## Идентичность и физическая связность

Owner key строго `(user,user_id)` или `(company,company_id)`. Один и тот же номер в разных типах не совпадает. Личная и корпоративная colony участника не объединяются. Рассматриваются только существующие planet_colonies с завершёнными проектами на одной surface/revision.

Граф — вершины-сектора, рёбра только из канонических Neighbors, с одинаковым owner key и проверенным проходом. Land%, географическое соседство и отсутствие случайного дерева по отдельности недостаточны.

**Политика для сектора с несколькими островами:** на канонической сухой маске, расширенной на радиус персонажа, определяем connected dry-components. Опорной для начальной P2 является наибольшая компонента; равенство разрешается устойчивым порядком глобальных координат. Только порталы, достижимые внутри этой компоненты, участвуют в связности. Площадка размещается в ней. Иначе одна вершина-сектор могла бы ложно соединить два непроходимых острова. Малые отдельные острова остаются видимой географией, но не становятся отдельными территориями/посадками P2. Это консервативное правило к утверждению, не терраформирование.

Сторона hex определяется двумя общими вершинами; samples границы вычисляются один раз для пары `(min_sector,max_sector,revision)`, не независимо в каждом секторе. Портал — интервал, где есть достаточная ширина сухого прохода и обе опорные компоненты достижимы. Реки/озёра, радиус персонажа и непроходимые участки исключаются. Диагональный контакт в одной точке не является проходом.

Постоянные леса/камни раскладываются после выбора проходов. Для каждого включённого портала резервируется путь от опорной области; декор не перекрывает его или площадку/spawn. Поэтому декоративный seed не изменяет юридическую связность. Если layout не может выполнить это требование, сцена не считается ready, показывается ошибка подготовки.

Connected components через BFS/DFS. Cache key включает surface revision, claims_epoch и walk_policy_version; «ID компоненты» — производный ключ, не постоянный FK. Модули привязаны к colony и сохраняют свои ID при любом merge.

## Один ответственный обработчик

Площадки создаёт cosmic colonies reconciler. Pure terrain/territory переиспользуются обеими службами; runtime не делает встречный INSERT.

`AdvanceColonies` завершает все проекты текущего tx и увеличивает claims_epoch/dirty поверхности, без генерации 256×256 и без ожидания планетарного процесса. После commit cosmic worker:

1. Берёт короткий согласованный read snapshot: revision, все completed colonies/owner keys, существующие площадки, текущий claims_epoch. Сортирует sector/id.
2. Вне tx/world lock рассчитывает dry policy, граф компонентов и предложения площадок. Формат layout/version и выбор кандидата детерминированны.
3. В коротком tx берёт прежний world lock, проверяет неизменность revision/claims_epoch/владений. При конфликте отбрасывает результат и повторяет; не записывает старое размещение.
4. В каждой компоненте с хотя бы одной enabled площадкой не создаёт новую. Все существующие площадки остаются на местах. В компоненте без площадок выбирает безопасный кандидат по устойчивому порядку секторов и клеток и INSERT с UNIQUE colony.
5. Фиксирует processed_epoch только вместе с площадками. Нет безопасного места — записывает pending/error с причиной и retry, не кладёт объект в воду. No-op retry не создаёт площадку заново.

Существующий world lock сериализует короткий commit и завершения проектов; новый долгий глобальный lock не добавляется. Два соседних проекта одного тика видны worker одновременно. Если один уже успел получить модуль до завершения второго — второй присоединяется к его компоненте без нового INSERT.

Dirty marker переживает crash и служит durable очередью; не нужен внешний брокер. Таймаут worker не отменяет уже завершённую колонизацию. Уведомления разделяются: «Колонизация завершена» и «Площадка готова»; первый не обещает мгновенную высадку до подготовки инфраструктуры.

## Размещение

Footprint площадки и свободный spawn-коридор целиком внутри hex, вне воды/речных масок/непроходимости и на опорной dry-component. Координаты quantized сохраняются у cosmic writer; nature generator обязан их учитывать как reserved zone. Позиция при перезагрузке не пересчитывается. Недостаточно поставить anchor на сушу, если остальная платформа выступает в океан.

Существующие площадки не переносятся после merge. Если площадка становится недоступной из-за административной смены revision, её нельзя молча переиспользовать. Новый snapshot — отдельная контролируемая операция с backfill, после закрытия визитов.

## Операции и ожидаемый результат

| Событие | Результат |
|---|---|
| Первый отдельный сектор | Один стартовый модуль |
| Соседний проходимый того же owner | Расширение без нового модуля |
| Удалённый сектор / непроходимая водная граница | Самостоятельная компонента со своей площадкой |
| Сектор соединяет две компоненты с модулями | Сохраняются оба, третьего нет |
| Присоединяется к нескольким компонентам, хотя бы одна имеет площадку | Новая не нужна; все имеющиеся сохраняются |
| Личный рядом с корпоративным | Две разные owner-components; пеший переход возможен только после отдельной проверки прав на оба сектора |
| Разделение территории | Пересчёт; компоненты без площадки получают одну безопасную либо понятный pending |
| Передача владения в будущем | Доступ следует текущей colony; бывший владелец лишается доступа. Передачу как новую механику сейчас не реализуем |
| Повтор worker / конкурентное завершение | Тот же итог без дубликатов |
| Нет места | Нет терраформирования/списания; pending с причиной |

## Старые колонии и удаление

Backfill использует те же dirty markers и reconciliation, не INSERT на каждый сектор. Сначала группировка, затем одна недостающая площадка на компоненту. Владельцы, проекты, ресурсы, уже полученные уведомления/возвраты не пересоздаются.

Сейчас завершённую отдельную colony пользователь не удаляет; существующая административная reset-процедура удаляет поверхность целиком. Логику split оформляем чистым алгоритмом и проверкой графа, не добавляя в P2 новую пользовательскую кнопку удаления/передачи. Если такая операция появится, её commit обязан пометить surface dirty. Reset/geography deletion защищаются barrier из DATABASE; ручное SQL-удаление вне API не считается поддерживаемой игровой операцией.
