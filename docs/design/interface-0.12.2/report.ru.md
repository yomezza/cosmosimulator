# Исправления интерфейса Cosmosimulator 0.12.2

Дата: 29 октября 2026. Основа: 0.12.1. [Исходное задание](spec.ru.md).

## Голограммы: причина и исправление

В 0.11.0 увеличивалась высота CSS-контейнеров, но изображение вписывается с сохранением пропорций и часто ограничено шириной колонки. Главное ограничение оставалось внутри SVG: общий viewBox 900×560 резервировал пространство для длинных частиц двигателя даже у неподвижного корабля. Дополнительно коэффициент footprint `.48 + .52 * length / 92` оставлял начальным кораблям много пустого пространства. Увеличение высоты коробки почти не увеличивало видимый корпус.

В генераторе введены две вычисляемые области просмотра: `data-idle-viewbox` для корпуса и `data-moving-viewbox` с двигателями и частицами. Они охватывают все 49 кадров полного оборота, сохраняют пропорции и запас для линий/свечения. Коэффициент видимого размера централизован в генераторе: `.80 + .20 * length / 92`, с сохранением умеренной разницы размеров классов. Новые SVG по умолчанию используют область неподвижного корпуса; общий компонент UI.updateHologram выбирает подходящую область при изменении состояния движения. Увеличение не достигается обрезанием двигателя.

Размер контейнера «Корабля» задаётся одним основным правилом: `--ship-hologram-height` с базовым значением 300 px, для узкого контейнера — 250 px. На верфях — `--shipyard-hologram-height`, 210 px. Существующие дублирующие поздние переопределения удалены. Левая колонка корабля получила равную долю ширины. Маленькие превью планировщика сохраняют контейнер 100×70 px. На верфях и в «Корабле» используется существующий общий компонент, отдельный механизм отображения не создан. SVG-фон остаётся прозрачным.

## Планировщик

Существующие группы по кораблю стали нативными ветками `details/summary`. Внутри каждая карточка задачи также раскрывается независимо: заголовок остаётся видимым, подробности и кнопки скрываются. У корабля есть стандартный индикатор раскрытия; у вложенной задачи — маркер браузера. Статусы, приоритеты и серверное выполнение не меняются при сворачивании.

Расширен существующий UI.fold: сохранение в localStorage включается явно только для новых веток планировщика. Ключ включает игрока и идентификатор корабля/задачи. Перед перерисовкой сохраняется фактическое состояние DOM, поэтому обновление данных не раскрывает ветки. Повторное открытие, смена языка и перезагрузка страницы сохраняют выбор. При недоступном localStorage остаётся память текущей страницы. Новых серверных таблиц нет.

## Фильтры карты

Существующее меню «Отображение» перенесено в верхнюю панель карты. Оно доступно при любой вкладке инспектора и при скрытой правой панели.

| Категория | Галактика по умолчанию | Система по умолчанию |
|---|---|---|
| Собственные корабли | Показаны | Показаны |
| Корабли других игроков | **Скрыты** | **Показаны** |
| Подписи | Включены, с прежним ограничением возле курсора | Включены |
| Владения корпораций | Показаны | Не применимо |
| Гиперкоридоры | Показаны | Не применимо |
| Порты, планеты, месторождения | Не применимо | Показаны |

В localStorage используются отдельные настройки для игрока и каждого режима. Скрытие чужих кораблей в галактике не скрывает их в системе. Фильтр гиперкоридоров не меняет расчёт путей: линия построенного маршрута сохраняется. Данные кораблей и игровых объектов фильтры не удаляют.

## Игроки в подсказке системы

Используется действующий ответ `/api/fleet`: собственные корабли и `public_ships`, где сервер уже возвращает только публичную информацию о кораблях других игроков и исключает ботов. Дополнительных запросов за именами при наведении нет. Имена вставляются через textContent, как и остальная подсказка.

По каждому новому снимку флота строится индекс «система → уникальные владельцы». На систему хранится максимум 11 владельцев: этого достаточно для 10 имён и признака продолжения. Несколько кораблей одного владельца дают одно имя. При отсутствии кораблей игроков выводится «Нет игроков». Фильтры маркеров на состав подсказки не влияют. При поступлении нового снимка обновляется и уже открытая подсказка.

Присутствие определяется полем `ships.star` из серверного снимка, а не онлайн-сессией. Для корабля в межсистемном полёте сохраняется существующая семантика сервера: его система изменится после фактического прибытия. Искусственное присутствие в промежуточных точках анимации не создаётся.

## Ограничения

Настройки хранятся в конкретном браузере и не синхронизируются между устройствами. Подсказка актуальна на момент последнего штатного обновления флота, а не получает отдельный сетевой поток. Существующая загрузка публичного флота остаётся прежней: фильтр скрывает отрисовку, но не сокращает сетевой ответ. Для очень больших флотов оптимизация этого ответа требует отдельного измерения; нагрузочный тест промышленного масштаба в этот выпуск не входит. Дополнительный индекс присутствия строится один раз на снимок флота, а не на каждое движение мыши. Механизм подписей карты возле курсора не изменён.

При движении область просмотра шире, чтобы полностью показать частицы; поэтому корпус визуально меньше, чем на стоянке. Это преднамеренное вписывание всей анимации, без обрезания. Новых миграций и изменений игровых механик в выпуске нет.
