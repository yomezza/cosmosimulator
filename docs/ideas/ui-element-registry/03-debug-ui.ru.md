# Cosmosimulator — административный Debug UI: функциональная спецификация идеи v1

**Статус:** утверждённые продуктовые правила; конкретная реализация подлежит проектированию и тестированию.  
**Связанные документы:** [идея](01-idea-v1.ru.md), [реестр и ID](02-naming-convention.ru.md).

## 1. Где включать

В верхнем административном меню предусмотреть **раздел/команду «Отладка интерфейса»** с окном настроек Debug UI. В окне:

- Переключатель **«Debug UI»**: включено / выключено (изначально выключено).
- Подрежим **«Просмотр»**.
- Подрежим **«Выбор элемента»**.
- Краткая инструкция: «Наведите на элемент, чтобы увидеть ID; наведите на ID для полного имени на русском/английском, сокращений и типа».
- При необходимости переключатель показа рамки и полезные настройки доступности, но **ID на наведённом элементе показывать обязательно**, а не опционально.

Текущий `#admin-menu` в `index.html` содержит штатные пункты, в т. ч. «Статус служб», но такого Debug UI пока нет: это **проект будущей функции**, а не описание уже работающей панели.

**Не путать** «Статус служб», будущие «Настройки служб» и «Отладку интерфейса»: это разные административные функции и разные `element_id`.

Предлагаемые ID команд: `shell.admin.menu.debug-ui`, `administration.debug-ui.window`, `administration.debug-ui.toggle`, `administration.debug-ui.mode.view`, `administration.debug-ui.mode.pick`.

## 2. Поведение выключенного режима

При `OFF`:

- Интерфейс визуально и функционально совпадает с обычным UI.
- Нет подсветки, бейджей, панелей идентификаторов, обработчиков перехвата, задержек или дополнительных данных для игроков.
- Не выполняется обход DOM / Canvas hit-test только ради Debug UI.
- Действующие подсказки `data-help`, контекстные меню, hover-эффекты и клавиатурная навигация не меняют поведения.

## 3. Поведение включённого режима

### 3.1. Наведение / фокус на элемент

Когда администратор подводит курсор к реестровому элементу (или выбирает доступный по клавиатуре элемент):

1. Элемент выделяется ненавязчивой рамкой/контуром; не использовать изменение размеров/layout.
2. Рядом появляется **маленький бейдж с полным каноническим ID**, например `market.local.item.context-menu`.
3. Бейдж остаётся доступным для наведения и клика; не исчезает, когда курсор переходит с элемента на него.
4. Если вложенные элементы имеют отдельные ID, выбирается **наиболее конкретный осмысленный элемент**, без мигания/скачков на каждую декоративную вложенность.
5. При переходе курсора между элементами информация обновляется без накопления множества старых подсказок.

**ID, а не только сокращение, должен быть постоянно виден для текущего наведённого элемента.** Текст ID можно выделить/copy вручную, а также кнопкой.

### 3.2. Наведение на бейдж ID

При наведении на сам **отображённый идентификатор** раскрывается карточка:

| Поле | Пример |
|---|---|
| Идентификатор | `market.local.item.context-menu` |
| Полное русское название | Компактное контекстное меню товара локального рынка |
| Полное английское название | Local market item compact context menu |
| Краткое русское название | ЛР-ККМ |
| Краткое английское название | LM-CCM |
| Тип | Контекстное меню |
| Базовый компонент | `ui.context-menu.compact` — Компактное контекстное меню / Compact context menu — **ККМ / CCM** |
| Модуль | Локальный рынок |
| Экземпляр | Например, тип товара `iron`, если безопасен для показа |

Команда **«Копировать ID»** копирует канонический ID; отдельное действие **«Копировать полную ссылку на элемент»** может копировать безопасный контекст экземпляра. Не включать токены, приватные DTO и закрытую серверную информацию.

Если ID элемента зарегистрирован, но перевод/сокращение отсутствует, показывать явное предупреждение о неполной записи вместо молчаливого выдумывания названия.

## 4. Два подрежима

### Просмотр

- Hover/focus идентифицирует элемент.
- Обычные клики по кнопкам, навигация, выпадающие меню, drag/resize, графики и игровые действия продолжают работать.
- Копирование ID выполняет только явное действие администратора.

### Выбор элемента

- Администратор нажимает на элемент, чтобы выбрать и закрепить его ID/сведения.
- Клик, используемый для выбора, **не исполняет игровое действие**: не покупает товары, не тратит кредиты, не удаляет записи/галактики и не перемещает персонажа.
- Для опасных элементов важно блокировать не только `click`, но весь необходимый набор событий активации (например, `pointerdown`/`pointerup`, touch и keyboard activation), насколько он участвует в управлении.
- Выбранный элемент виден в карточке до следующего выбора / выхода из режима; ID можно скопировать.
- Переход в «Просмотр», выключение Debug UI или потеря прав возвращают обычное поведение.
- При открытии вложенных меню предусмотреть отдельный безопасный способ **раскрыть родительские пункты без выполнения действий**, чтобы можно было выбрать вложенный пункт. Не блокировать само наведение на пункт, которое открывает подменю.

**Безопасность важнее полного охвата с первого дня:** если безопасный захват действия не обеспечен, явно помечать элемент «недоступен для выбора» вместо риска случайно выполнить операцию.

## 5. Окна, контекстные меню, Canvas и деревья

- **Окна:** отдельные ID у корневого окна, заголовка, управления окном (свернуть/развернуть/закрепить/закрыть), содержимого и значимых разделов. У текущего `ui/windows.js` набор кнопок нужно сверить фактически; не заявлять кнопку «свернуть» в каждом окне, если её нет.
- **Контекстные меню:** отдельные ID у меню, группы, вложенного подменю и действий. Компонент `UI.menu` может переиспользовать DOM-узел; реестровый ID конкретного вызова нужно передавать/привязывать при каждом построении, иначе разные модули будут показывать один и тот же ложный идентификатор.
- **Dropdown/picker:** сохранять правильное позиционирование и слой отображения. Не путать штатные `<details>`-меню с `UI.menu`, пока аудит не подтвердил совместимость поведения.
- **Списки/таблицы/деревья:** ID типа строки/ветви плюс безопасные поля контекста экземпляра. Раскрывающие узлы навигации и промежуточные узлы маршрута — разные значения `kind`.
- **Canvas/SVG карты:** стандартный DOM hover возвращает только общий `canvas`. Для звезды, сектора, точки маршрута, дерева/камня/персонажа сцены нужны адаптеры **семантического hit-testing**, использующие существующую модель попаданий рендерера. Не создавать сотни тысяч overlay-DOM нод.
- **Персонажи и природные объекты:** ID у семантического типа (`planet.scene.nature.tree`), контекст конкретного объекта только при наличии доступного стабильного ключа. Скрытые/неразведанные объекты и секретные сведения не подсвечивать только из-за Debug UI.
- **Динамические и временные окна:** удаление/пересоздание не должно оставлять зависшие выделения; связь с текущей сессией/владельцем проверяется.

## 6. Доступ и приватность

- Включать только по **актуальной серверной роли администратора**, не по одному localStorage-флагу и не по скрытой кнопке.
- Отладочный режим относится только к интерфейсу **конкретного администратора**, не переключает UI других пользователей и не должен требовать изменения игровых данных в БД.
- Рекомендуемое сохранение состояния — browser/account-scoped настройка в существующем `core/preferences.js`. При выходе/смене аккаунта/утрате прав немедленно сбрасывать активный overlay; восстанавливать только после новой проверки прав.
- Debug UI **не** открывает чужие приватные данные, не вызывает административные API ради «просмотра всего», не показывает секреты в контекстных ключах.
- Пользовательские имена и контент не вставлять как непроверенный HTML в Debug-карточку.
- В режиме «Выбор» при ошибке / потере фокуса не выполнять исходное действие отложенно.

## 7. Совместимость и реализация без второго UI-framework

Использовать существующие механизмы `internal/server/web`:

- `ui/windows.js`: модули и управление окнами.
- `ui/menu.js`: существующее `UI.menu`, `ui/floating.js` — общий overlay host и позиционирование.
- `ui/tooltip.js`: существующие подсказки; приоритет Debug-карточки и предотвращение их конфликта должны быть явно определены.
- `core/preferences.js`: персистентность выбранных настроек.
- `core/i18n.js` / `ru.json` / `en.json`: язык UI; **реестровые RU/EN имена доступны одновременно независимо от текущего языка**.
- `features/maps/galaxy.js` и `features/planet/*`: предметные адаптеры попаданий в интерактивные объекты, не переносить игровую математику в общий `ui`.
- `styles/tokens.css`, `styles/terminal.css`: общие токены/классы с локальным отладочным namespace; не смешивать их со стилями игры.

Предполагаемый минимум данных разметки: `data-ui-id="market.window.close"` для конкретных DOM-элементов. Это **пример новой будущей разметки**, а не требование переименовать существующие `id`. Для `UI.menu` и Canvas нужны отдельные адаптеры.

## 8. Приёмочные тесты

1. OFF: обычный UI полностью идентичен исходному, включая производительность.
2. ON/View: наведение на кнопку/поле/окно/меню/вкладку показывает правильный **полный ID**.
3. Hover на **ID** показывает оба полных названия (RU/EN), оба сокращения, тип, модуль и копирование.
4. Одинаковый `component_id`, но **разные ID** для меню рынка и планеты; ни один из них не выдаёт себя за другое.
5. ON/Pick: выбор «Купить», «Удалить» и других опасных действий не отправляет игровую команду.
6. Вложенные меню доступны для диагностического просмотра и выбора дочерних пунктов.
7. Динамические строки, деревья, узлы маршрута и интерактивные объекты Canvas различимы по типу и контексту.
8. RU/EN, узкий экран, масштабирование и клавиатурная навигация; нет блокирующей подсказки за пределами экрана.
9. Переключение режима, logout, потеря админских прав, перезагрузка/новая сессия безопасны.
10. Нет рассинхронизации между фактическими ID и машинным реестром; отсутствующие показываются как `unregistered`, но это не подмена реестра случайным CSS-селектором.
11. Нет скрытой выдачи токенов/внутренних данных; сведения реестра не подменяют настоящую авторизацию.

**Итог:** Debug UI — инспектор согласованных имён, а не новый слой игровых полномочий и не инструмент выполнения административных команд.
