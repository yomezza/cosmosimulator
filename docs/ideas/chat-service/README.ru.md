## Самое важное перед реализацией

- Все новые обычные DB objects — префикс chat_; используется одна существующая PostgreSQL и DB_SCHEMA.
- Реальные пользователи/сессии и компании принадлежат Cosmic; Chat не создаёт их копий.
- Реальная текущая позиция/сектор принадлежат Planet. В репозитории на этапе P2-3 нет необходимой authoritative visit state: **Planet/Sector chat остаётся выключен до реализации и теста Planet-owned row fence**.
- Cosmic outage блокирует Chat полностью; Planet outage — **только Planet и Sector**, остальные работают при готовых Cosmic+Chat.
- Corporation нельзя включать, пока текущий company_dissolve не использует durable запрос и подтверждённую физическую зачистку Chat; нельзя использовать прямой DELETE.
- Требуются атомарные idempotent operations, уникальные канальные seq, единая машина состояний Private, одно live Chat WS per account с поколением lease, настоящий DELETE original и корректная судьба saved copies.
- Резервные копии/WAL могут содержать удалённые тексты; отчёт о восстановлении обязан учитывать возможность восстановления из точки до удаления. SQL DELETE ≠ мгновенная криптографическая очистка физического носителя.

## Статус проверки

Документарный аудит и проектирование выполнены. Схема не апробирована выполнением миграций, Postgres EXPLAIN, нагрузочным экспериментом, Go race или UI e2e — эти проверки составляют **обязательную работу Codex**, а не выполненный результат. Игровой код сейчас не менялся.

Разработка только по отдельному согласованному поручению, с результатами тестов и без незаметного изменения утверждённых правил.
