# Chat Service — передача frontend-прототипа разработчику (v13)

**Дата фиксации:** 2026-10-31  
**Статус:** согласованный в чате *интерактивный демонстрационный макет* на вымышленных данных; **не production-код**, не интегрирован с Go и Chat API.  
**Исходный файл:** [chat-service-ui-prototype-v13.html](./chat-service-ui-prototype-v13.html).  
**Источник требований:** [01-idea-v1.ru.md](./01-idea-v1.ru.md), [02-approved-decisions.ru.md](./02-approved-decisions.ru.md), [14-frontend-design-task-v1.ru.md](./14-frontend-design-task-v1.ru.md) и обязательные уточнения 05–13. При конфликте правил продукты 01/02 первичны; технические исправления 08–13 имеют приоритет над старыми техническими предложениями. Поздние визуальные пожелания владельца отражены ниже.

## 1. Что сохранено и как запускать

Весь согласованный **код демоверсии v13** — HTML, CSS, vanilla JavaScript, вымышленные данные, кликабельные меню/формы и локальная бизнес-симуляция — находится **целиком** в одном `chat-service-ui-prototype-v13.html`. Внешних npm-пакетов, сервера, сборки, запросов к API и WebSocket нет. Можно открыть файл напрямую в браузере. Это воспроизводимый **визуальный/UX-эталон**, а не готовый модуль для копирования целиком в `internal/server/web`.

Файл показывает также макет главной страницы Cosmosimulator v0.17.0 (верхнюю панель, левое меню, показатели пилота/корабля/кредитов, нижний статус). **Эти части уже существуют в игре** и в реальной реализации не должны дублироваться. Внедрять нужно только интерфейс и взаимодействия Chat Service.

Не переносить в production тестовые обработчики прочих модулей, mock API, автосоздание игроков, тестовые состояния служб и тестовые переключатели ролей. Источником сообщений, доступа, прочтений, приглашений, наказаний и срока хранения всегда является сервер.

## 2. Кнопка «Чат» в левом меню: точное место

**Порядок нижних кнопок:**
1. **Чат** — первая кнопка нижней группы.
2. **Руководство пилота**.
3. **Предложить идею**.

В макете это `#sidebar > button[data-chat-open].chat-bottom` сразу **после «Планировщик задач» и перед «Руководство пилота»**. Класс `.chat-bottom` прижимает эту группу вниз через `margin-top:auto`. В настоящей игре соответствующий `margin-top:auto` уже назначен `.sidebar-bottom` у «Руководства пилота»; **перенести маркер нижней группы на кнопку чата**, иначе чат окажется не в той части списка.

Для production добавить кнопку в `internal/server/web/index.html`:
```html
<button type="button" class="sidebar-bottom" data-open="chat" data-nav="Чат" aria-label="Чат">
  <span class="nav-icon"><!-- иконка через действующую систему ui/icons --></span>
  <span class="nav-label" data-i18n="Чат">Чат</span>
</button>
```
Рядом остаются существующие `data-open="guide"` и `data-open="ideas"`. Согласовать новый SVG-путь с `features/shell/icons.js`, а заголовок и tooltip — с `I18n` и существующей навигацией. Не создавать второй обработчик `[data-chat-open]` в игре: **это временное имя обработчика автономного HTML**.

Нажатие «Чат»: если floating закрыт — открыть; если уже открыт — сфокусировать; если закреплён на главной — прокрутить к закреплённому чату, а не создавать другое окно. Подсветка кнопки согласуется с `module-open`.

## 3. «Закрепить на главной» — принципиально НЕ обычный pin

**Floating:** обычное перемещаемое/изменяемое по размеру окно модуля, ориентир **420 × 540 px**, с прямыми углами. В production окно создавать через `Modules.create("chat", …)` и обслуживать существующими `ui/windows.js` / `Modules.open/focus/close`. Не переносить из демо самодельный `pointerdown/pointermove` drag, `resize:both` и собственный z-index-менеджер.

**Home-docked:** действие **«▣ На главную»** физически перемещает *тот же единственный chat-root* из оболочки floating в `#chat-home-slot` на **главной странице**, а не «прикрепляет» плавающее окно к экрану. Точка монтажа — **сразу после `.overview-stats` и перед `.workspace-intro`** внутри `#game`, чтобы карточки баланса, местоположения и хронологии оставались выше чата. Чат становится элементом потока страницы и занимает **50% доступной ширины основной области** на desktop; вторая половина остаётся **пустым резервом под будущие новости** (`#news-home-slot`). Новости сейчас не реализовывать и не придумывать для демонстрации.

**Актуальная высота после последних согласований:** **825 px** на desktop (в 1,5 раза больше первоначального макета 550 px); при адаптивном режиме в демо **780 px** до 880 px и **795 px** до 550 px. Сообщения скроллятся внутри, а не бесконечно растягивают страницу. На узких экранах — одна колонка чата на всю доступную ширину, резерв новостей скрыт.

**«↗ В окно»** возвращает чат в floating, сохраняя вкладку, личную беседу, черновики, scroll anchor/положение, настройки и геометрию последнего floating-окна. Не пересоздавать контроллер, не дублировать DOM, fetch и **WebSocket**. `w.pinned` из `ui/windows.js` всего лишь запрещает передвижение обычного модуля — **не использовать его как значение home-dock**. В production нужен отдельный `chat-dock-mode` и единственный жизненный цикл ChatController.

В прототипе DOM: `#home-lower-grid > #chat-home-slot + #news-home-slot`; отдельно `#chat-floating`; **один** `#chat-root` перемещается через `append()` в `setDock()`. В реальной интеграции реализовать такой переход с публичным API Modules и чисткой приватного runtime на выходе из аккаунта.

## 4. Экран, режимы и согласованное поведение

Шесть вкладок в **строгом порядке**: **★ Избранное → Global → Planet → Sector → Corporation → Private**. При отсутствии доступного Planet presence вкладки Planet/Sector не допускают чтение/отправку. Без корпорации Corporation скрыт/недоступен в соответствии с серверными правами.

- **Сообщения:** плотные терминальные строки без массивных «пузырей»; автор, динамический тег текущей корпорации, время, текст/эмодзи, reply. В Planet до сообщения показывается исходный номер сектора; у недоступного оригинала ответа — «Исходное сообщение недоступно». Контекстное меню через «⋯» и доступ с клавиатуры/touch.
- **Общее компактное меню:** у сообщений, папок, записей «Избранного», Private-бесед — высота строки **21 px**, минимальная ширина **120 px**, длинные действия расширяют меню только по необходимости. В production **переиспользовать `UI.menu` из `ui/menu.js`** и добавить только локальные chat-scoped компактные CSS-модификаторы; **не копировать самодельный `#chat-pop-menu` как второй фреймворк**.
- **Избранное:** виртуальное системное представление **«Все»** (не пользовательская удаляемая папка), тестовые папки **«Маршруты»**, **«Полезное»**, личные заметки и независимые сохранённые копии. У папки «⋯» → «Переименовать»/«Удалить». У сохранённой записи «Переместить в папку» открывает **компактное вложенное меню** с актуальными пользовательскими папками и пунктом «Без папки (Все)», текущая помечена; выбор применяет перемещение без дополнительного модального шага. Удаление папки не удаляет записи.
- **Private:** список DM, групп и приглашений; узкое floating-окно показывает либо список, либо выбранную переписку с «Назад»; группа с владельцем и участниками. Действие называется **«Пригласить игрока»**, не «Пригласить третьего игрока». Ошибочный ник показывать **под полем приглашения** с красной обводкой, не как системное уведомление; успешное действие подтверждать коротким toast. В outgoing Private серая точка — не прочитано другими, синяя — прочитал **хотя бы один** другой участник; по hover/focus/tap — оформленный tooltip с пояснением.
- **Игроки:** отдельное компактное окно по кнопке в заголовке канала; поиск, число участников, ник, тег корпорации, online/offline, роль владельца в группе. Global — онлайн; Planet — текущая планета; Sector — текущий сектор; Corporation — текущая корпорация, включая offline; Private — участники открытой беседы. Источник списков и прав должен проверяться сервером.
- **Модерация:** в Corporation отдельная кнопка **для руководителя / корпоративного модератора / игрового администратора**, но не для обычного члена. Окно участников, действующих mute, истории и жалоб. Сроки только **5 мин / 30 мин / 1 час / 24 часа / 7 дней**, причина обязательна для наказания и модераторского удаления. Руководитель может ограничивать других, включая корпоративных модераторов; модератор — только обычных членов, не себя/руководителя/других модераторов; досрочное снятие mute по правилам 01/02/05. Mute запрещает **только отправку** в Corporation, сохраняет чтение/поиск. Жалобы через «⋯», администратору доступно рассмотрение жалоб; причины, служебный доступ и журналы — с соблюдением privacy/ACL. UI-проверка роли — **не безопасность**.
- **Эмодзи:** компактная кнопка **☺** возле отправки, панель с категориями «Частые / Эмоции / Жесты / Космос / Предметы», поиск, вставка в текущую позицию курсора, многократная вставка без закрытия. Встроена в Global/Planet/Sector/Corporation/Private. Ограничения: 256 Unicode code points для общих каналов, 500 — Private; сервер обязан проверять лимиты. Допустимы текст, эмодзи и игровые ссылки, но не HTML/файлы.
- **Прозрачность:** настройка непрозрачности фона **40–100%** с шагом **5%**, по умолчанию 100%. Менять alpha **фона**, не CSS `opacity` общего родителя, чтобы текст, кнопки, tooltip оставались контрастными.
- **Индикатор служб:** точка в заголовке; зелёная, когда **Cosmos (Cosmic) и Planet** доступны; оранжевая, когда доступна только одна; красная, когда обе недоступны либо отдельно недоступен Chat Service. Красивая короткая подсказка: две строки **Cosmos** и **Planet**, перед каждой зелёный/красный **квадратик**, справа состояние; в области счётчика символов **нет** текста «Cosmic/Planet недоступен». При Cosmic down весь Chat закрыт для пользовательских действий, при Planet down блокируются лишь Planet/Sector, при Chat down — статус «Нет соединения» и запрет отправки.

Остальные состояния из 14: loading/empty/denied/disconnected/muted/pending invitation/deleting/error; read receipts только при фактическом показе сообщения, а не при доставке WS. После reconnect черновик **не отправляется автоматически**.

## 5. Что реально повторно используется, а что новое

**Важное различие:** standalone HTML **визуально воспроизводит** существующую верстку, но **не импортирует** оригинальные файлы игры: токены и часть базовых правил скопированы/адаптированы внутрь единственного `<style>`, а обработчики имитируют возможности `Modules`. Поэтому сказать «прототип уже использует production UI API» было бы неверно.

| Ресурс настоящего фронтенда | Что переиспользовать в production |
|---|---|
| `internal/server/web/styles/tokens.css` | Существующие цвета и переменные: `--bg`, `--panel`, `--border`, `--muted`, `--text`, `--accent`, `--focus`, `--action-*` |
| `internal/server/web/styles/terminal.css` | Настоящие стили header, footer, sidebar, `.overview-stats`, `.workspace-intro`, `.module-window`, кнопок/пикеров/строк и responsive; никаких глобальных замен |
| `internal/server/web/ui/windows.js` | `Modules.create/open/close/focus`, drag/resize/z-index, сохранение геометрии, очищение и window switcher |
| `internal/server/web/ui/menu.js` | `UI.menu` и вложенные context submenus с локальной компактной темой |
| `internal/server/web/ui/tabs.js`, `ui/tooltip.js`, `ui/floating.js` | Существующие вкладки, keyboard/ARIA, подсказки, позиционирование overlay |
| `internal/server/web/core/preferences.js` | Account-scoped настройки докинга/прозрачности/звука/последней вкладки; назначить один источник истины для каждой |
| `internal/server/web/core/lifetime.js`, `core/session.js` | Единый контроллер, dispose listeners при logout/смене аккаунта, epoch guards |
| `internal/server/web/features/shell/app.js` | `#game`, события `signedout`/`snapshotaccepted`/`sessionexpired`; не перерисовывать чат при каждом snapshot |
| `internal/server/web/features/shell/navigation.js`, `features/shell/icons.js` | Регистрация окна chat, выделение пункта боковой панели, обычные иконки |
| `internal/server/web/ru.json`, `en.json` | Локализация всех новых строк, aria-label, ошибок, подсказок |

**Новые классы/узлы, разработанные именно в прототипе** (потребуются новые chat-scoped стили, их не было как действующих компонентов игры): `.home-lower-grid`, `#chat-home-slot`, `#news-home-slot`, `.chat-root`, `.chat-titlebar`, `.chat-tabs`, `.chat-section-header`, `.chat-area`, `.chat-message`, `.chat-compose`, `.chat-context-menu`, `.chat-status-tooltip`, `.chat-read-tooltip`, `.chat-read-dot`, `.chat-players-overlay`/`-panel`, `.chat-moderation-overlay`/`-panel`, `.chat-modal`, `.chat-folder-bar`, `.chat-emoji-panel`, `.chat-emoji-grid`, `.chat-mentions`. Все новые селекторы желательно изолировать `#window-chat` / `.chat-*` / `#chat-home-*`. Не импортировать в игру общие правила `body`/`button`/`header`/`footer` из макета.

**Новые JS-процессы, которые нужно интегрировать, а не просто скопировать:** `setDock`, `renderTabs`, `renderBody`, `renderCompose`, `messageMenu`, `folderOptions`, `favoriteOptions`, `conversationActions`, `renderPlayersWindow`, `renderModerationWindow`, `renderChatStatusTooltip`, `showChatReadTooltip`, `renderEmojiPicker`, `insertEmoji`, `showModal`/`modalError`. В production разделить их по ответственности между `features/chat/*`, не оставлять один 70-килобайтный IIFE с глобальными слушателями. Не дублировать системы окон/контекстных меню.

## 6. Предлагаемый способ интеграции для Codex

1. Не менять 01/02. Ознакомиться с `14-frontend-design-task-v1.ru.md` и `12-codex-execution-brief-v1.1.ru.md` + обязательным `13-last-mile-integration-fixes.ru.md`.
2. Добавить в `index.html` кнопку «Чат» и `#chat-home-slot` после `.overview-stats`; не трогать структуру существующих карточек.
3. В `features/shell/navigation.js` зарегистрировать окно Chat через `Modules.create`, обеспечить режим dock/undock без двойного окна и без использования старого `pinned` как dock-mode.
4. Создать минимальные `features/chat/index.js` (controller/lifecycle), `view.js` (DOM и доступность), `state.js` (view model и drafts), `actions.js` (UI actions), `transport.js` (один Chat WS) и отдельный локальный CSS слой с префиксом `chat-`. Это **рекомендация о разбиении**, а не уже существующие файлы.
5. Заменить mock-массивы в HTML реальными DTO/API/WS, не вводя ещё одну авторизацию в браузере. Подписки снять на logout, данные/черновики полностью очистить при `signedout`, `sessionexpired` и смене account ID. Не сохранять личные тексты/историю в `localStorage`. В макете `localStorage` содержит только demo-предпочтения opacity/dock.
6. Доступ, список игроков, отправка, приглашения, поиск, права модерации, жалобы, прочтение, антиспам и TTL должны подтверждаться backend. Отказы после смены сектора/компании/состава Private — отображать, не делать скрытого повторного send.
7. Встроить локализацию RU/EN, клавиатурные переходы и `aria-label`/`aria-expanded`/`aria-modal`; адаптировать активные контекстные меню к существующему `UI.menu`. Отдельно проверить доступность меню и emoji-панели при 200% zoom.

**Ограничения запуска функций:** Planet/Sector не включать до подтверждённого Planet-owned presence/sector fence. Corporation/модерация не включать до проверенных корпоративных ограничений и удаления компании. Это описано в 12/13; внешне красивый UI сам по себе не подтверждает готовность backend.

## 7. UI-приёмка, которую обязан пройти разработчик

- 1440×900, 1280×720, ~900px, 375px, 200% zoom, без горизонтального переполнения; test floating resize и dock 50%/825px; не перекрываются баланс/местоположение.
- Меню слева: «Чат» первым в нижней группе; collapse/expand; нажатие во время dock не создаёт дубль.
- Dock→floating→dock: сохраняются выбранный раздел, текущая Private-беседа, черновик, scroll, настройки, нет второго WS.
- Chat status: зеленый/оранжевый/красный + две строки tooltip Cosmos/Planet с квадратами; availability правильно блокирует разделы; ошибки служб не показаны возле счётчика символов.
- «Избранное»: виртуальная «Все», папки, действия «⋯» по 21px, перенос в вложенном menu, удаление папки сохраняет записи.
- Private: invitation form c inline error неверного ника, роль владельца, read dots и tooltip, unread, подтверждение удаления; соблюдаются реальные права.
- Corporation: обычный игрок не видит модерации; глава и модератор ограничены разными ACL; обязательная причина, пять сроков, read/search разрешены при mute.
- Emoji: вставка в caret, поиск/категории, limit, Enter и Shift+Enter, длинные emoji sequences, RU/EN.
- Logout/account switch: исключена утечка чужих текстов/приглашений/настроек; WS не раздваивается.
- E2E/regression настоящих окон, `UI.menu`, `Modules.clearPrivate`, `Preferences`, общих стилей и исходной домашней страницы.

## 8. Что не следует принимать за готовую реализацию

- Готовый HTML **не реализует Chat API, Go-сервис, миграции PostgreSQL, реальную ACL/health, WS lease, серверные действия, доказательство прочтения и корректную чистку персональных данных**. Вся локальная «логика» существует исключительно для демонстрации визуального поведения.
- Демо `data-module`, `#demo-window`, контекстный `#chat-pop-menu`, модалки и `setDock` — иллюстрации, которые следует **подключать к существующей игровой инфраструктуре**, не копировать её заново.
