# Chat Service — утверждённые продуктовые решения (дополнение к v1)

Дата согласования: 2026-10-30. Статус: **утверждено владельцем**, не код и не техническое ТЗ.
Источник: [01-idea-v1.ru.md](./01-idea-v1.ru.md) и последовательное согласование механик.
Правило: нижеследующие новые решения имеют приоритет при явном расхождении с 01; остальные уже утверждённые требования 01 сохраняются. Не переносить предложения из обсуждения в статус «утверждено» без явного согласия.

## Private: индивидуальные беседы и преобразование в группу

- Создатель личного диалога вправе пригласить третьего игрока **без согласия второго собеседника**. После принятия третьим игроком существующий диалог преобразуется в группу, и приглашённый получает доступ ко **всей сохранившейся истории**. До принятия диалог остаётся личным; отправитель каждого сообщения вправе удалить свои сообщения для всех. Обратного преобразования группы в личный диалог нет.
- Между одной парой игроков существует не более **одного активного личного диалога**. Встречные приглашения этой пары автоматически засчитываются как взаимное согласие и открывают **одну** беседу. После преобразования прежнего диалога в группу пара может завести новый личный диалог с нулевой историей.
- Приглашение действует **7 дней**; после отказа повторное приглашение **того же игрока в ту же беседу** запрещено **24 часа**. Не более одного активного приглашения одному адресату в конкретную беседу. Лимит предложенных пользователем приглашений — **20 отправлений одному и тому же адресату одним отправителем за сутки** суммарно по беседам; точный rolling-window алгоритм — проектная детализация. Успешное встречное приглашение не должно создавать дубликат диалога.
- Исключённый участник может вновь вступить в группу только по новому приглашению владельца и после принятия; аналогично добровольно вышедший. После вступления доступна вся сохранившаяся история.
- Группа создаётся из чернового состояния и **активируется первым принятым приглашением**. До этого её создатель может переименовать группу и рассылать приглашения, но отправлять сообщения нельзя. Если **все** приглашения черновой группы отклонены либо истекли, черновик автоматически удаляется.
- Только **текущий владелец** группы вправе менять её название, приглашать/исключать участников, передавать право владельца, удалять беседу для всех (с подтверждением).
- При добровольном выходе владелец вручную передаёт права действующему участнику, если группа после выхода продолжит существовать. Новый владелец получает все полномочия прежнего, прежний не сохраняет привилегий. Приглашённые, ещё не принявшие приглашение, не могут стать владельцами.
- Группа из **двух** игроков остаётся группой. Если после выхода/исключения участника в группе остаётся **один**, группа автоматически удаляется. Для выхода, ведущего к удалению, передача владельца не требуется.
- Выход **любого** участника личного диалога удаляет беседу для **обоих**; для нового общения потребуется новое приглашение.
- Автоматическое удаление беседы физически удаляет её текст из активной БД, закрывает доступ и аннулирует ожидающие приглашения. Независимые копии в «Избранном» сохраняются, кроме удаления модератором конкретного оригинала за нарушение согласно 01.

## Corporation: управление

- Руководитель может наказывать **других** участников, в том числе корпоративных модераторов; обычный корпоративный модератор — только участников без полномочий модератора. Модераторы не наказывают руководителя, друг друга или себя; игровой администратор имеет более высокие полномочия. Ограничения действуют на отправку в Corporation, не на чтение.
- Лимит отправки Corporation: **одно сообщение в секунду на отправителя**.
- Причину удаления/ограничения видят наказанный, корпоративные модераторы и игровые администраторы; другим участникам её не раскрывать.
- Игровой служебный доступ к чужим Corporation журналируется; руководителю корпорации список служебных просмотров не показывается.

## Упоминания, прочтение и уведомления

- Упоминать `@имя` можно в Global — существующего игрока; в Planet/Sector — присутствующего в текущей области; в Corporation — участника корпорации; в Private — участника открытой беседы. Реализация по стабильному user ID, а не по тексту переименуемого имени.
- `@all` разрешён **в Corporation и в беседах Private**; не разрешён в Global, Planet и Sector. Уведомлять только тех, кто имеет право читать соответствующую беседу. Антиспам/отдельный лимит массовых уведомлений требуется спроектировать.
- Прочтение Private наступает, когда сообщение появилось в **видимой части открытой беседы**, а не при доставке. При входе в группу старая история доступна, но не увеличивает счётчик непрочитанного. Серая/синяя отметка прочтения остаётся как в 01 (хотя бы один получатель).
- При персональном упоминании появляются уведомление и звук (если разрешён настройками); `@all` обрабатывается как групповое упоминание с защитой от спама. В первой версии системные сообщения фиксируют вступления/выходы/исключения/смену названия и владельца, а корпоративные события модерации видны только адресатам с нужными правами. Системные сообщения не тратят лимит пользователя, TTL совпадает с TTL соответствующей беседы.

## Избранное, поиск, жалобы

- При удалении личной папки её записи сохраняются в «Все»; дубли одной сохранённой копии разрешены. Поиск: русский/английский без учёта регистра, подстроки, точные эмодзи; без исправления опечаток и интеллектуального поиска.
- Жалобы на сообщения входят в v1. При наведении на сообщение появляется **«…»**, по нажатию — контекстное меню минимум с **«Сохранить в избранное»** и **«Пожаловаться»** (остальные разрешённые действия — «Ответить»/«Удалить» по правам). На сенсорных устройствах должен быть альтернативный способ открытия меню.
- Служебный журнал модерации хранится **180 дней**, содержит метаданные действий и причину, но не скрытый архив удалённого текста.

## Отказы и зависимости служб

- При потере связи с Chat Service UI **показывает статус отсутствия соединения**.
- **Изменение относительно 01:** если **Cosmic Service или Planet Service** подтверждённо недоступна, блокируется **весь пользовательский чат**, а не только Planet/Sector. Кратковременный единичный сетевой сбой не должен давать ложного мгновенного отключения. После восстановления — повторная проверка актуального доступа/присутствия до возвращения функций.

## Что не утверждено данным дополнением

Конкретный алгоритм скользящих лимитов, длительность heartbeat и health grace, судьба пустого черновика без приглашений, точные контракты API/WS, СУБД-схема, структура партиций и cron, резервные копии, свойства и роли пользователей, модерационные процедуры, порядок конкурентных операций — предмет проектного ТЗ. Важное новое правило о полной зависимости от Planet Service **может конфликтовать** с текущей независимостью космического процесса; такое отклонение обязательно отразить в интеграционном плане.
