# Проверка космического терминала · 0.14.1

Проверка выполнена после разделения web-клиента на ES-модули и Go-сервера на пакеты. Повод: при переносе со станции в трюм появлялась ошибка, хотя ресурс иногда уже оказывался в корабле.

## Подтверждённые проблемы и исправления

| Проблема | Причина и решение |
|---|---|
| Ложная ошибка после успешного переноса | Логистика вызывала удалённую глобальную `window.refresh`. POST проходил, затем браузер падал на обновлении. Теперь импортируется реальный snapshot-store, обновляются и снимок игры, и склады. |
| Старые тесты пропускали этот дефект | Harness искусственно восстанавливал прежние globals. Удалены подставные `window.refresh`, UI, api и прочие; тесты используют отдельный `__testApp` только для инспекции. Проверка AST запрещает обращения к несуществующим globals. |
| Обновление трюма прерывало перетаскивание | `Object.assign` превращал getter `dragging` в неизменное значение false. Getter теперь установлен через `Object.defineProperty`. Открытие ветки при drag проверяет актуальность сессии и DOM. |
| Старая ошибка логистики могла появиться после закрытия/выхода | Результат и ошибка чтения принимаются только для текущего запроса, сессии и открытого модуля. |
| «Отменить» оставляло введённые административные значения | Сохранённый локальный draft восстанавливался поверх серверных значений. При отмене настроек процесса/редактора пользователя очищается draft соответствующих полей. POST при отмене не выполняется. |
| Доставка могла подставить отсутствующий порт | Убрана жёсткая ссылка на систему 5. Начальное значение выбирается из настоящего списка станций; без станций создание недоступно. |
| «На карте» из уведомления могло не выбрать систему | Событие отправлялось до инициализации карты и не переключало её режим. Сначала открывается модуль, затем используется `showstar` с сохранением отложенного выбора. |
| Поздний ответ карты мог затронуть другую сессию | Загрузка системы и фоновое обновление галактики сверяют epoch и актуальный запрос/мир. Устаревшие ошибки не показываются. |
| Дополнительные административные окна колонизации оставались после потери роли | Окнам назначена admin-аудитория, они удаляются при потере прав. Повторная проверка роли выполняется после чтения; поздний ответ не открывает окно заново. Сохранение настроек не показывает старые уведомления. Серверная проверка прав сохранена. |
| В карточке объекта появлялось выдуманное `0 / 0` | Общий таймер ожидал атрибуты запаса даже у простого отсчёта времени. Префикс количества выводится только там, где эти атрибуты существуют. |
| Планировщик не видел купленные после его открытия корабли | Список picker обновляется при изменении состава/имён флота, сохраняя существующий выбор. Обновление списка само не запускает команду. Действия планировщика дожидаются повторного отображения очереди. |

Повторное нажатие после старой ошибки не является способом «доделать» предыдущий перенос: его серверная часть уже могла завершиться. Для проверки фактического состояния используются свежий снимок трюма и склады. Новых миграций данных в этом выпуске нет.

Настоящий Chromium открывает **21 модуль на RU и EN** против Go API и PostgreSQL, затем выполняет действия: перенос, rename, заправка, покупка/продажа, покупка корабля, очередь задач, идея, создание корпорации, пополнение/снятие, роль, выдача ресурса, открытие настроек колонизации, тик и очистка уведомлений. Менеджер колоний проверяется отдельно. Это не только подмена API ответами.

## Воспроизводимость и ограничения

Команды и требования среды: [tests/ui/README.ru.md](../../tests/ui/README.ru.md). Синтетические проверки не подключаются к внешнему серверу. Реальный браузерный сценарий вызывается Go-тестом на собственном loopback-сервере с одноразовым nonce и отдельной тестовой схемой. Полный DB-прогон и race-прогон выполняются на созданных для этого одноразовых базах; игровые данные не используются.

Браузерный DB-сценарий добавлен в GitHub Actions рядом с обычными UI-тестами. Windows-службе Node/Playwright не нужны.

Проверка охватывает перечисленные основные сценарии и существующие автоматические проверки, но не все возможные комбинации имущества, задержек, размеров галактик и действий игроков. Проверялся Chromium на Linux; нативная служба Windows/SCM, другие браузеры и предельный стресс-тест не проверялись. Полноценная внутренняя 2D-симуляция планетарного сервера ещё не реализована и не входит в этот выпуск.

## Установка

Остановить службу, заменить EXE сборкой `cosmosimulator-v0.14.1-windows-amd64.exe`, запустить и обновить страницу терминала. Параметры подключения прежние; чистить localStorage, сбрасывать мир или перегенерировать планеты не требуется. Старые версионные сборки сохранены в downloads.
