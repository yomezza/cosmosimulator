## Что добавлено в M0

Минимальный Node test runner и Playwright, изолированные синтетические API-фикстуры, проверки пользовательского поведения и отдельные TODO-требования к известным дефектам. В Go добавлены проверки запрета anonymous API до обращения к БД и доставки embedded assets/CSP/MIME. Workflow `UI contracts` запускает браузерную и независимую Go-проверку при изменениях кода и тестов.

API fixtures не являются реализацией авторизации или игровой экономики. Browser mocks не доказывают транзакционные гарантии PostgreSQL. Изменяемые игровые данные остаются ответственностью текущей службы; M0 не запускает второй сервер, не меняет DB_SCHEMA и не применяет миграции.

## Контрольные изображения

Две сцены исходного интерфейса на синтетических данных, Chromium, 1440×1000. Они просмотрены при подготовке этапа и показывают сохранённое размещение очередей/счётчиков, inline-голограммы и отдельного трюма. Это иллюстрации для ревью, **не автоматические pixel-golden assertions**. Точное положение анимированной SVG и реальное время в footer могут отличаться при повторном запуске.

## Граница этапа и откат

Игровой JS/HTML/CSS, SQL, HTTP API, сборка Windows-службы и версия 0.12.5 не меняются. Существующие версионные EXE сохраняются. Нового исполняемого файла или релиза для тестового этапа нет.

Откат M0 удаляет только добавленную тестовую инфраструктуру, workflow и документацию. Никакой миграции или восстановления игровых данных не требуется. Следующий этап M1 — владелец асинхронных запросов и пилот Users; он выполняется отдельно по правилу поэтапного согласования.
