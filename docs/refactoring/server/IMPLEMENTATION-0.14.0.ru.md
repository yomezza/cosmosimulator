# Отчёт о разделении Go-сервера · 0.14.0

Основание: 0.13.0, `d52eb299292019c74092aaec7146df1c29276c6f`. Дата: 29 октября 2026.

Выполнен рефакторинг **самого Go-сервера**. Вместо единого пакета с HTTP, экономикой, генерацией, очередями и колонизацией создан модульный монолит с явными зависимостями. В корне `internal/server` осталось три Go-файла: `app.go` (сборка), `routes.go` (HTTP), `run.go` (запуск/остановка). Игровые правила, SQL-операции и фоновые обработчики перенесены к владельцам в отдельных пакетах. Интеграционные тесты вынесены в подкаталог, чистый тест галактики — к universe, насыщенный кеш — к worldstore.

[Карта всех пакетов, границы и правила дальнейшей разработки](README.ru.md).

## Существенные изменения устройства

- `App` больше не является объектом с методами всех подсистем. Composition root связывает отдельные Service с используемыми зависимостями.
- Отдельно выделены canonical geography/resources/universe, флот и навигация, исследования/добыча, wallet/inventory/logistics, рынки/верфи/доставка/боты, корпорации, planner, colonies и simulation.
- Shared platform не импортирует игровые features. Pure geography/universe/resources не зависят от HTTP или PostgreSQL. Это проверяется архитектурным тестом.
- Чистое подключение и космическая initialization разделены. Migration/seed получают SQL filesystem явно и не являются скрытым эффектом конструктора Service.
- Benchmark использует фабрику полного HTTP приложения из composition root на временной схеме; обратного импорта server нет.
- World cache и station cache принадлежат worldstore; транзакционное чтение использует соединение вызывающего. Cache invalidation при commit сохраняет прежнюю синхронизацию.
- Валидация текста и digest вынесены из логистики/идей в узкие инфраструктурные пакеты. Идентичность существующих receipts сохранена.

Это не смена игровых правил и не новый планетарный сервер. Существующие обработчики HTTP сохраняют endpoint, JSON и проверки доступа. Общая PostgreSQL, DB_SCHEMA, lock order, атомарность экономики и прежняя каноническая география сохранены. Все 496 SQL-литералов runtime и набор из 59 зарегистрированных HTTP route patterns совпали при независимом сравнении старых и новых исходников.

## Проверки

Итоговые журналы: [полный PostgreSQL](checks/postgres.txt), [браузер](checks/browser.txt), [целевой race](checks/race.txt). Браузерные фикстуры не подменяют настоящие транзакционные проверки PostgreSQL.

- Полный `go test ./... -count=1` с отдельной одноразовой PostgreSQL 17: **79 верхнеуровневых PASS, 0 FAIL, 0 SKIP**.
- Целевой `-race` конкурентной логистики, последнего корабля, чистого подключения/schema, насыщенного world cache и изолированного benchmark HTTP приложения: **7 PASS, 0 FAIL, 0 SKIP**.
- `go vet ./...` — чисто.
- Браузерные регрессии существующего интерфейса: 45 PASS, 0 FAIL/SKIP/TODO.
- Тест границ пакетов.
- Пять контрольных сериализованных миров/поверхностей и четыре набора значений публичного sampler совпали с эталонами 0.13.0.
- Чистая Windows amd64 сборка с embedded HTML/ES modules/CSS/PNG/SVG; сохранение старых EXE и SHA256.

Функциональный benchmark проверялся с одним виртуальным игроком и пятисекундным mixed-сценарием; он выполняет реальные HTTP-запросы и SQL, проверяет завершение/очистку временной схемы и неизменность исходного кошелька. Это проверка изоляции и соединения компонентов, не измерение предельной нагрузки.

Полный race всего набора не объявляется выполненным: для текущего выпуска выбран целевой набор конкурентных сценариев. Он не заменяет отдельный будущий стресс-тест планетарного runtime.

## Обновление и границы

Существующую службу остановить и заменить EXE версионной сборкой 0.14.0. Переменные `DATABASE_URL`, `DB_SCHEMA`, `HTTP_ADDR`, proxy/origin/cookie configuration остаются прежними. Новой SQL-миграции нет; сброс клиентских preferences и перегенерация планет не нужны. Windows-службе не нужны npm и отдельный web-каталог.

Будущий planetary runtime использует `platform/postgres.Open`, канонический geography sampler, модели и проверку сессии по согласованному контракту. Он не вызывает cosmic initialization/tick и не становится вторым владельцем кредитов, космического трюма или территории. Отдельные DB roles, межсервисный обмен грузом, active character state и sector simulation требуют своей реализации.

Откат — прежний 0.13.0 EXE при остановленной службе; новый выпуск не вводит отдельного формата хранимых данных. Старые сборки сохранены в downloads.
