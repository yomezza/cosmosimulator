# Контракты интерфейса — этап M0

Тесты запускают исходные HTML/JS/CSS/SVG из `internal/server/web` на временном loopback-порту. Все API перехватываются; неожиданный endpoint, мутация, внешний URL или JavaScript exception проваливают проверку. Адрес настоящего сервера не настраивается. Go, PostgreSQL и реальные аккаунты браузерным тестам не нужны.

Node и Playwright нужны **только разработчику и CI**. Windows-служба продолжает запускаться одним EXE.

## Запуск с чистого checkout

Нужен Node 22 или новее:

```sh
cd tests/ui
npm ci --ignore-scripts --no-audit --no-fund
npx playwright install chromium
npm test
```

На Linux при отсутствии системных библиотек: `npx playwright install --with-deps chromium` (устанавливает системные зависимости, может требовать повышенных прав). CI использует эту команду на одноразовом runner.

Если Chromium уже установлен, загрузка браузера не обязательна:

```sh
CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm test
```

`CHROMIUM_NO_SANDBOX=1` предназначен только для изолированной среды разработки, где Chromium иначе не запускается. По умолчанию sandbox не отключается. Тесты не используют абсолютные пути среды Codex.

## Что проверяется

`baseline.test.mjs` фиксирует правильное текущее поведение: startup/auth/retry; односимвольный пароль; отсутствие ложной дельты баланса; сохранение ветки «Карты»; перемещение/размер/pin/Escape/геометрию окна; очереди и счётчики двух кораблей; независимость фильтров galaxy/system и аккаунтов; текущую добычу; inline-голограмму и отдельный трюм; категории руководства; поиск/страницы/клавиатуру picker; вложенное меню; RU/EN; технические toast без записи в inbox; закрытие административного модуля для игрока; очистку при logout; отсутствие ранней загрузки planet.js/PNG.

`known-defects.test.mjs` содержит **требования к будущим исправлениям**, а не утверждения «ошибка должна остаться». Пять подтверждённых дефектов помечаются TODO в выводе Node: поздний Users response после выхода, заголовок повторного подтверждения, picker после уменьшения viewport, disabled после callback, HTTP status при не-JSON ответе. TODO не означает исправление и не считается PASS. Если требование начинает выполняться, `knownDefect` намеренно проваливает запуск: необходимо убрать обёртку и оставить обычный регрессионный тест в соответствующем этапе.

`npm run test:baseline` проверяет только поддерживаемые контракты, `npm run test:known` — известные дефекты. `npm test` запускает оба файла последовательно.

TODO отмечается только на вложенном требовании; родительский сценарий и проверки чистоты фикстуры не являются TODO. Поэтому неожиданные browser/API errors не маскируются известным дефектом. Сейчас 16 baseline и 5 диагностических сценариев дают 26 tests / 21 pass / 5 todo с учётом вложенных требований; parent PASS не означает, что известная ошибка исправлена.

Фикстуры в `fixtures.mjs` синтетические и минимальные. Они повторяют DTO, необходимые проверяемым сценариям, но не реализуют экономику или серверную авторизацию. Нельзя считать mock 403 доказательством защиты Go API. Реальные anonymous guards и доставку embedded assets отдельно проверяет `internal/server/ui_contracts_test.go`. Проверка полномочий вошедшего игрока остаётся в интеграционных Go-тестах.

## PostgreSQL и будущая планетарная служба

Без БД:

```sh
env -u TEST_DATABASE_URL go test ./... -count=1
go vet ./...
```

Эти команды выполняются из корня репозитория. Интеграционные DB-тесты будут SKIP. Для полного интеграционного прогона использовать только **одноразовую** PostgreSQL-базу с суффиксом `_test`, созданную специально для проверки; существующие тесты создают и удаляют схемы, некоторые обращаются к `public`. `DATABASE_URL` рабочей службы нельзя копировать в `TEST_DATABASE_URL`. Один суффикс `_test` не доказывает, что база безопасна для удаления тестовых объектов.

Граница двух серверов и правила будущего общего DB-кода описаны в [архитектурном контракте](../../docs/refactoring/service-boundaries.ru.md). В M0 новая служба и общие production-пакеты не создаются.

## Границы покрытия

Это минимальная исходная проверка, а не полное покрытие игры. Не проверены все 26 групп preferences, все административные мутации, конкурентная экономика, реальные планшеты и screen reader. Chromium не заменяет Firefox/Safari. Автоматического pixel-golden сравнения нет; контрольные изображения синтетических сцен служат иллюстрациями исходного состояния. При переносе очередного модуля добавляются проверки его конкретных действий, отмены/поздних ответов и сохранения draft.
