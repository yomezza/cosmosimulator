# Cosmosimulator · 0.3.1

Лёгкая браузерная космическая экономическая песочница: Go + PostgreSQL, встроенный HTML/CSS/JavaScript. Один Windows x64 `.exe`, без npm и отдельного сервера интерфейса.

## Запуск в Windows

Нужна существующая база PostgreSQL 17 или совместимой версии. Создавать отдельную базу для игры не обязательно: `DB_SCHEMA` выбирает схему, по умолчанию `public`. Отсутствующая схема создаётся автоматически при наличии права `CREATE` на базу. Альтернатива — заранее создать схему в нужной базе:

```sql
-- Роль cosmos должна существовать; команда выполняется в вашей существующей базе.
CREATE SCHEMA cosmosimulator AUTHORIZATION cosmos;
```

Пользователь службы должен владеть игровой схемой или иметь `USAGE`, `CREATE` и нужные права на её таблицы и последовательности. Не используйте схему с чужими таблицами `users`, `ships`, `companies` и другими именами приложения.

PowerShell:

```powershell
$env:DATABASE_URL = 'postgres://cosmos:YOUR_URL_ENCODED_PASSWORD@127.0.0.1:5432/existing_database?sslmode=disable'
$env:DB_SCHEMA = 'cosmosimulator'
$env:HTTP_ADDR = '127.0.0.1:8080'
# Только для первоначального создания администратора:
$env:ADMIN_USERNAME = 'operator'
$env:ADMIN_PASSWORD = 'YOUR_UNIQUE_PASSWORD_AT_LEAST_12_BYTES'
.\downloads\cosmosimulator-v0.3.1-windows-amd64.exe
```

Откройте `http://localhost:8080`. Для остановки нажмите Ctrl+C. После создания администратора удалите переменные `ADMIN_USERNAME` и `ADMIN_PASSWORD`. Существующие пароли bootstrap не меняет, аккаунт игрока автоматически не повышает. `.env.example` — справочник: `.env` автоматически не читается.

`DB_SCHEMA` — одно точное имя, не список схем. Имена с пробелами/кавычками экранируются, длина ограничена 63 байтами. Системные схемы и специальное имя `$user` запрещены. Смена схемы не переносит данные. Настройка применяется ко всем соединениям пула, без автоматического поиска таблиц в `public`.

Для доступа извне настройте HTTPS reverse proxy, `PUBLIC_ORIGIN=https://your-domain`, `COOKIE_SECURE=true` и подходящий `HTTP_ADDR`. `sslmode=disable` предназначен для локальной БД; для удалённой используйте проверяемый TLS, например `sslmode=verify-full`. Не коммитьте строки подключения и пароли.

## Windows-служба и обновление

Файл поддерживает Service Control Manager. Проверьте консольный запуск, затем скопируйте выбранную версию из `downloads` в `C:\Cosmosimulator\cosmosimulator.exe`. В PowerShell администратора:

```powershell
sc.exe create Cosmosimulator binPath= 'C:\Cosmosimulator\cosmosimulator.exe' start= auto
New-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Services\Cosmosimulator' -Name Environment -PropertyType MultiString -Value @('DATABASE_URL=postgres://cosmos:YOUR_URL_ENCODED_PASSWORD@127.0.0.1:5432/existing_database?sslmode=disable','DB_SCHEMA=cosmosimulator','HTTP_ADDR=127.0.0.1:8080') -Force
sc.exe start Cosmosimulator
sc.exe query Cosmosimulator
```

Окружение службы отличается от окружения окна PowerShell. Ограничьте доступ к её настройкам, содержащим пароль БД. Перед обновлением остановите службу, сделайте резервную копию схемы и замените установленный `.exe` новой версией. Запускайте только одну версию сервера на одной схеме: старые версии не обрабатывают новые задания добычи. Миграции выполняются автоматически при старте с транзакцией и advisory lock. Прежняя карта, аккаунты, трюмы и кредиты сохраняются. Нативная Windows-служба поддержана кодом, но в облачной Linux-среде проверены кросс-компиляция и работа Linux-сервера, не реальный SCM.

## Интерфейс модулей

Слева находится сворачиваемая панель: карта, корабль, разведка и добыча, рынок, компании и корпорации. Главная страница содержит только сводку. Статус соединения — слева в футере.

Окна независимы: можно открыть несколько, перенести за заголовок, изменить размер за нижний правый угол, закрепить кнопкой ⌖ и закрыть кнопкой × или Escape. Закрепление запрещает перемещение и изменение размера. Положение, размеры, закрепление и состояние панели сохраняются в браузере. При недостаточном размере окно предлагает увеличить его вместо показа обрезанного интерфейса. Стрелки на выбранном заголовке перемещают незакреплённое окно.

Вверху находится профиль с никнеймом: из его меню открываются профиль игрока и настройки языка. Доступны русский и английский, выбор сохраняется в браузере. Подсказки с пунктирным подчёркиванием раскрывают смысл параметров при наведении или фокусе клавиатурой. `G` — спектральный класс, `M☉` — солнечная масса, `L☉` — солнечная светимость, `AU` — астрономическая единица, `K` — кельвины, `g` — земная сила тяжести.

Переводы хранятся в `internal/server/web/ru.json` и `en.json`, модуль — `i18n.js`. Для нового языка нужны словарь с теми же ключами, код в списке поддерживаемых языков и пункт выбора.

## Галактика и системы

Эдем содержит 1000 звёзд, 2916 двунаправленных гиперкоридоров, четыре связанных рукава по 245 систем и 20 изолированных звёзд. Пересечения линий не создают соединений. BFS ищет кратчайший путь по числу переходов. Галактика сохраняется в PostgreSQL; seed `20261026`. Существующие координаты, классы звёзд и коридоры при обновлениях не заменяются. Генератор принимает количество систем, но для существенно больших миров понадобится оптимизация квадратичного поиска соседей.

Нажатие на звезду переключает карту галактики на карту её системы. Также можно ввести номер системы и нажать «Открыть систему». Кнопка «К галактике» возвращает общий вид. Локальный вид показывает орбиты планет, астероидный пояс, ледяное поле в чётных системах и станцию в системах, номер которых не делится на 3. В ED-0001 и ED-0005 станция гарантирована. Объекты можно выбрать на карте или в списке справа. Орбиты поясов и станций масштабируются по квадратному корню светимости звезды: ледяное поле не располагается в зоне испарения только из-за фиксированного расстояния. Орбиты схематические, расстояния нормализованы для читаемости. До разведки видны орбитальные контакты и приблизительные физические свойства, но не месторождения.

У звезды 3–7 планет с массой, гравитацией, атмосферой и равновесной температурой. Температура приближена из светимости и расстояния при нулевом альбедо и равномерном распределении энергии, без парникового эффекта. Новые галактики получают преимущественно маломассивные звёзды; в сохранённом мире старые классы остаются. Карта кешируется сервером; ручное изменение её JSON в БД требует перезапуска.

Регионы и специализации:

- Кузни Сварога — Орихалк.
- Сады Гесперид — Амброзия.
- Пределы Айн Соф — Азот алхимиков.
- Мандала Акаништхи — Ваджра.
- Безмолвие Техом — Агни; этот регион охватывает изолированные системы.

Ресурсы используют культурные названия, не утверждения о реальных химических веществах: Орихалк — античный металл, Ваджра — индийский символ алмаза/громового жезла, Azoth — алхимический агент (не химический азот), Агни — игровая марка топлива в честь ведийского божества огня, Амброзия и Манна — агроресурсы из греческой мифологии и библейского повествования. Происхождение названия доступно в подсказке. Агроресурсы и газы пока собираются общим действием извлечения; фермы и специализированное оборудование не моделируются.

## Добыча, корабль и уровень

Все начинают в ED-0001 с кораблём «Пилигрим»: трюм 60, бак 40, топливо 30. Разведка текущей системы стоит 10 CR и даёт 10 XP; повторная бесплатна. Данные разведки принадлежат аккаунту.

Кнопка «Добыть 3» теперь запускает сохраняемое задание, а не немедленное начисление. Материал резервируется в месторождении, 3 места в трюме — под результат. Прогресс показывается в модуле добычи. На следующем мировом тике груз автоматически поступает в трюм, появляется уведомление и начисляется 5 XP. Новый цикл требует нового нажатия; бесконечная автоматическая добыча не включена. Пока цикл не завершён, перелёт запрещён. Запас каждого месторождения — 1000; добыча идёт партиями по 3.

Корабль перемещается только по существующим путям: 2 топлива и 5 секунд на переход. Во время перелёта торговля, разведка и добыча недоступны. 1 Агни в трюме восстанавливает до 5 топлива. Срок прибытия сохраняется; прибытие восстанавливается запросом, в том числе после перезапуска. Несвязанные рукава пока недоступны стартовому кораблю.

Уровень принадлежит игроку, отображается в профиле и повышается вручную: требуются `100 × текущий уровень` XP и столько же CR, которые расходуются. Максимум 100. Уровень пока не даёт скрытых бонусов к кораблю или добыче.

Учебное производство ORE сохранено в модуле добычи отдельно от планетных ресурсов: 1 ORE на игрока за тик и продажа по 5 CR. Оно связано с профилем и служит начальным источником дохода; это не стационарная шахта в фиктивном Kepler Belt. Интерфейс показывает текущую систему. Экономика поэтому пока не является полностью замкнутой.

## Рынок и бронирование

Локальный рынок доступен только при наличии станции и прибытии корабля. Покупка сразу поступает в трюм. Цены зависят от региона, станции и запаса; каждая партия имеет фиксированную цену сделки. Станция стартует с конечным запасом и 5000 CR. Три бота раз в 3 тика торгуют на стартовой станции, расходуя свой груз и деньги; старой бесконечной выручки нет.

Глобальный рынок показывает станции и предварительную стоимость выбранного ресурса. Бронирование списывает кредиты в escrow и убирает товар из доступного запаса продавца. До получения груз остаётся на станции, не занимает трюм и не телепортируется. Для получения требуется прибыть в систему станции и иметь свободный трюм с учётом незавершённой добычи. Получение переводит оплату станции и выдаёт груз ровно один раз. Отмена возвращает всю оплату и товар в запас. Чужую бронь получить или отменить нельзя. Не более 100 активных броней на игрока; UI предупреждает об отсутствии пути к станции. Множество кораблей и автономные доставки пока отсутствуют.

## Компании и корпорации

Новый и мигрированный игрок становится участником общей «Академии Эдема» (`EDM`). Аккаунт больше не считается отдельной компанией. Можно выйти, вступить в существующую организацию или создать свою: полное имя 3–60 символов, уникальный код из 3–4 букв/цифр, цвет и флаг из набора символов. Членство одно; перед сменой нужно выйти. Владелец пока обязан оставаться в своей компании: управление передачей владения не реализовано.

«Компании» показывает организации с участниками в текущей системе или регионе; участники в перелёте не считаются присутствующими в системе отправления. «Корпорации» — глобальный реестр тех же организаций и создание своей. Отдельная иерархия холдингов, общие кошельки и приглашения не реализованы; вступление открыто.

## Администратор

Роли `player` и `admin` проверяются сервером. В верхнем меню администратора:

- «Пропустить тик» принудительно выполняет ровно один мировой тик, завершает положенные задания и сдвигает оставшееся время перелётов на 10 секунд. Меню после нажатия остаётся открытым. Автоматический тик сразу следом не дублируется.
- «Пользователи» открывает список до 200 аккаунтов. «Редактировать» открывает отдельное окно пользователя: имя, роль, кредиты, уровень, XP и необязательная смена пароля. Пустой пароль сохраняет прежний. Смена роли/пароля завершает сессии аккаунта. Ботам нельзя менять идентификацию. Нельзя понизить себя или последнего администратора.

Естественный тик — раз в 10 секунд. Добыча зависит от тиков работающего сервера; перелёт — от сохранённого срока. Простой не превращается в бесконечное число производственных тиков.

## Разработка, проверки и сборки

Go 1.26+, PostgreSQL. Из корня:

```sh
go mod download
go vet ./...
go test ./...
DB_SCHEMA=cosmosimulator DATABASE_URL='postgres://cosmos:password@127.0.0.1:5432/existing_database?sslmode=disable' go run ./cmd/cosmosimulator
```

Для интеграции нужна отдельная одноразовая база с именем, заканчивающимся на `_test`, и права создания схем. Тесты создают/удаляют временные схемы; никогда не указывайте рабочую игровую базу:

```sh
TEST_DATABASE_URL='postgres://cosmos:password@127.0.0.1:5432/cosmosimulator_test?sslmode=disable' go test -race -count=1 -v ./...
```

Без `TEST_DATABASE_URL` интеграционные тесты пропускаются. Проверяются авторизация, роли, миграции, изоляция схем, карта и пути, добыча по тикам, торговля и переполнение трюма, бронь и параллельное получение, компании, ручной тик, редактирование аккаунтов, опыт и повышение уровня.

Linux → Windows x64:

```sh
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -trimpath -ldflags='-s -w' -o downloads/cosmosimulator-v0.3.1-windows-amd64.exe ./cmd/cosmosimulator
sha256sum downloads/*.exe > downloads/SHA256SUMS
```

Каждое обновление получает новое имя файла с версией; старые `.exe` не перезаписываются. Проверенные исходники и сборка коммитятся вместе; тег `vX.Y.Z` запускает GitHub Actions, который прикладывает соответствующий `.exe`, описание из `release-notes/vX.Y.Z.md` и контрольные суммы. Новую версию не следует собирать поверх уже опубликованного файла.

Основные API: `/api/health`, `/api/state`, `/api/galaxy`, `/api/route`, `/api/system?id=N`, `/api/expedition`, `/api/profile`, `/api/profile/upgrade`, `/api/companies`, `/api/market/global`, `/api/admin/users`, `/api/admin/user`, `/api/admin/tick`. Изменения выполняются POST JSON с проверкой Origin; кроме health/static, нужна сессия. Пароли bcrypt, случайные сессионные токены хранятся в БД в виде хеша, cookies HttpOnly. `/api/state.companies` — старое совместимое поле списка игроков; актуальные организации выдаёт `/api/companies`.

Это ранняя версия: перед публичной MMO ещё нужны восстановление доступа, резервное копирование, защита от массовых регистраций и эксплуатационная настройка.
