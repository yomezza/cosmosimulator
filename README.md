# Cosmosimulator · 0.3.0

Легковесная браузерная экономическая песочница. Go + PostgreSQL, HTML/CSS/JavaScript без npm, сторонних шрифтов и CDN. Интерфейс встроен в один исполняемый файл.

## Что работает

- Регистрация, вход, выход; пароли bcrypt, сессии на 7 дней в PostgreSQL, HttpOnly cookies, проверка источника запросов, ограничение попыток входа.
- Роли `player` и `admin`. Регистрация всегда создаёт игрока. Администратор просматривает список пользователей; назначения ролей через браузер пока нет.
- Шахта каждого игрока производит 1 единицу руды каждые 10 секунд. Продажа всего запаса по фиксированной цене 5 CR. Начальный баланс 1000 CR.
- Три бота раз в 3 такта покупают или продают небольшие партии ресурсов на рынке ED-0001. Сделки используют реальные остатки трюма, кредитов и товаров станции. Это простые участники симуляции, не ИИ-агенты.
- Состояние мира сохраняется в базе. Во время выключения сервера производство останавливается. Общий такт атомарен и не удваивается при нескольких экземплярах сервера.
- Автоматическая начальная схема БД при запуске; блокировка и транзакция защищают параллельную инициализацию.

## Быстрый запуск в Windows

Требуется PostgreSQL 17 (либо совместимая версия) и доступ к существующей базе. Go для готового `.exe` не нужен. Сборка x64: `downloads/cosmosimulator-v0.3.0-windows-amd64.exe`.

Отдельная база не требуется: укажите существующую базу в `DATABASE_URL` и схему игры в `DB_SCHEMA`.
Если схема отсутствует, служба создаст её автоматически (нужно право `CREATE` на базу).
Можно заранее создать схему от имени администратора PostgreSQL и передать её пользователю службы:

```sql
-- Выполняется в уже существующей базе; роль cosmos должна существовать.
CREATE SCHEMA cosmosimulator AUTHORIZATION cosmos;
```

Для существующей схемы пользователь службы должен иметь `USAGE` и `CREATE` на схему, а также права на её существующие игровые таблицы и последовательности. Рекомендуется, чтобы роль службы владела отдельной схемой игры. Не используйте схему с чужими таблицами `users`, `sessions`, `world`.

PowerShell, из каталога репозитория:

```powershell
$env:DATABASE_URL = 'postgres://cosmos:YOUR_URL_ENCODED_PASSWORD@127.0.0.1:5432/existing_database?sslmode=disable'
$env:DB_SCHEMA = 'cosmosimulator'
$env:HTTP_ADDR = '127.0.0.1:8080'
$env:ADMIN_USERNAME = 'operator'
$env:ADMIN_PASSWORD = 'YOUR_UNIQUE_ADMIN_PASSWORD_12_OR_MORE_BYTES'
.\downloads\cosmosimulator-v0.3.0-windows-amd64.exe
```

Откройте `http://localhost:8080` в браузере. Остановка: Ctrl+C. Для других устройств задайте `HTTP_ADDR=0.0.0.0:8080` и настройте Windows Firewall. Не открывайте HTTP с паролями в интернет: используйте HTTPS reverse proxy, `COOKIE_SECURE=true`, `PUBLIC_ORIGIN=https://your-domain` и TLS к удалённой БД (`sslmode=verify-full`). `sslmode=disable` выше предназначен для локальной базы.

Имя аккаунта: 3–24 символа ASCII (буквы, цифры, `_`, `-`), регистр учитывается. Пароль: 12–72 байта UTF-8. Администратор создаётся только при явно заданных `ADMIN_USERNAME` и `ADMIN_PASSWORD`. Существующий пароль не перезаписывается, игрок не повышается до администратора. После первого запуска удалите эти две переменные: `Remove-Item Env:ADMIN_USERNAME, Env:ADMIN_PASSWORD`.

`DB_SCHEMA` задаёт одно точное имя схемы, а не список схем. По умолчанию используется `public` — старые установки продолжают работать. Схема применяется ко всем соединениям пула, включая новые подключения; обращения к таблицам не переходят автоматически в `public`. Имена с пробелами и кавычками поддерживаются, максимальная длина — 63 байта; системные схемы и специальное имя `$user` запрещены.

Чтобы сменить схему уже установленной Windows-службы, добавьте `DB_SCHEMA=cosmosimulator` в её параметр реестра `Environment` (сохранив `DATABASE_URL` и остальные настройки), затем перезапустите службу. Переключение схемы не переносит старые данные: другая схема — отдельное игровое состояние. Если хотите сохранить прежний мир, оставьте прежнюю схему или отдельно перенесите данные.

`.env.example` — справочник. Файлы `.env` автоматически **не загружаются**. Не коммитьте пароли и строки подключения.

## Windows-служба

Исполняемый файл поддерживает Windows Service Control Manager, имя службы `Cosmosimulator`. Сначала проверьте обычный запуск и создайте администратора. Затем скопируйте выбранную версию `.exe` в постоянный каталог, например `C:\Cosmosimulator`, под постоянным именем `cosmosimulator.exe` (архив в `downloads` сохраняет имя с версией). В PowerShell администратора:

```powershell
sc.exe create Cosmosimulator binPath= 'C:\Cosmosimulator\cosmosimulator.exe' start= auto
# Переменные именно для службы; подставьте свою строку подключения.
New-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Services\Cosmosimulator' -Name Environment -PropertyType MultiString -Value @('DATABASE_URL=postgres://cosmos:YOUR_URL_ENCODED_PASSWORD@127.0.0.1:5432/existing_database?sslmode=disable','DB_SCHEMA=cosmosimulator','HTTP_ADDR=127.0.0.1:8080') -Force
sc.exe start Cosmosimulator
sc.exe query Cosmosimulator
```

Служба получает настройки из своего окружения, а не из окна PowerShell. Ограничьте доступ к конфигурации службы: строка подключения содержит пароль. Остановка: `sc.exe stop Cosmosimulator`. При обновлении остановите службу, замените `.exe`, запустите снова. Запуск через SCM поддержан кодом, но в Linux-среде не проверялся на настоящей Windows.

## Разработка и проверки

Go 1.26 или новее, PostgreSQL 17. Из корня проекта:

```sh
go mod download
go test ./...
go vet ./...
DB_SCHEMA=cosmosimulator DATABASE_URL='postgres://cosmos:password@127.0.0.1:5432/existing_database?sslmode=disable' go run ./cmd/cosmosimulator
```

Для интеграционного теста создайте **отдельную одноразовую** базу `cosmosimulator_test`. Тесты создают в ней временные схемы и удаляют их после проверки; имя базы обязательно должно заканчиваться `_test`. Нужны права создания схем.

```sh
TEST_DATABASE_URL='postgres://cosmos:password@127.0.0.1:5432/cosmosimulator_test?sslmode=disable' go test -race -count=1 -v ./...
```

Без `TEST_DATABASE_URL` интеграционный тест пропускается. Он проверяет регистрацию, валидацию, вход/выход, запрет повышения роли, доступ администратора, защиту Origin, добычу, поведение ботов и продажу руды. Дополнительные тесты проверяют изоляцию двух схем в одной базе, разные соединения пула, безопасную обработку имени схемы и повторный запуск. `GET /api/health` проверяет соединение с БД.

Windows x64, из Linux:

```sh
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -trimpath -ldflags='-s -w' -o downloads/cosmosimulator-v0.3.0-windows-amd64.exe ./cmd/cosmosimulator
sha256sum downloads/*.exe > downloads/SHA256SUMS
```

Windows PowerShell:

```powershell
$env:CGO_ENABLED='0'; $env:GOOS='windows'; $env:GOARCH='amd64'
go build -trimpath -ldflags='-s -w' -o downloads/cosmosimulator-v0.3.0-windows-amd64.exe ./cmd/cosmosimulator
Get-FileHash .\downloads\cosmosimulator-v0.3.0-windows-amd64.exe -Algorithm SHA256
```

## Границы первого прототипа

Это базис для разработки, не готовая масштабная MMO: пока нет строительства, рынка ордеров, восстановления пароля, подтверждения email, резервного копирования и панели управления ролями. У администратора только просмотр аккаунтов. Первые 20 компаний отображаются по балансу. Перед публичным запуском потребуются эксплуатационная настройка и дальнейшее развитие защиты от злоупотреблений. При каждом обновлении исходники и Windows-сборка в `downloads` сохраняются вместе в Git.

## Галактика Эдем (Edem)

При первом запуске в выбранной `DB_SCHEMA` создаётся процедурная галактика из 1000 звёзд: четыре связанных спиральных рукава (по 245 систем) и 20 изолированных систем. Между рукавами нет коридоров. Системы — вершины графа, гиперкоридоры — двунаправленные рёбра. Пересечение линий на рисунке не создаёт соединение.

Карта и параметры генерации (seed `20261026`, версия генератора 1) сохраняются в таблице `galaxies` как JSONB. Перезапуск и обновление сервера не перегенерируют карту. `generateGalaxy(count, seed)` принимает количество звёзд: в дальнейшем можно увеличить размер без изменения формата данных; существующий мир при этом требует явного расширения/миграции. Нынешний поиск соседей при генерации квадратичный, для гораздо больших миров понадобится пространственный индекс. Отрисовка Canvas, масштабирование колесом, перемещение перетаскиванием, выбор системы кликом; ввод номеров систем доступен и без мыши.

Введите начальную и конечную системы и нажмите «Построить маршрут». Сервер использует BFS и возвращает кратчайший путь по числу переходов либо отсутствие пути. Прыжки между несвязанными системами невозможны. Планировщик дополнен кораблём и перелётами в v0.3.0: стоимость и время описаны ниже.

API (требуется авторизация): `GET /api/galaxy`, `GET /api/route?from=1&to=97`. Карту клиент загружает один раз, отдельно от обновлений экономики.

## Языки

«Настройки / Settings» в верхней панели позволяют выбрать русский или английский язык. Выбор сохраняется в браузере (`localStorage`) и применяется без перезагрузки, включая сообщения ошибок, карту и числа. Переводы находятся в `internal/server/web/ru.json` и `en.json`; модуль `i18n.js` управляет загрузкой словарей и переключением языка. Ключи — исходные русские строки, значения каждого файла — переводы соответствующего языка. Для нового языка добавьте словарь с теми же ключами, его код в список поддерживаемых языков модуля и пункт выбора в HTML. Названия компаний и стабильные идентификаторы систем не переводятся.

## Окно галактической карты

После входа нажмите «Галактическая карта» в футере. Откроется отдельное окно: карта слева, панель построения маршрута справа. Перемещайте окно за заголовок мышью или касанием; выбранный клавиатурой заголовок можно двигать стрелками. Закрытие — кнопкой «Закрыть» или Escape. Повторное открытие сохраняет масштаб, положение окна и выбранный маршрут до перезагрузки страницы. Можно пользоваться основной панелью компании, оставив карту открытой. На узких экранах панель маршрута располагается под картой, содержимое окна прокручивается.

Каждая Windows-сборка сохраняется в `downloads` с версией в имени: `cosmosimulator-v0.3.0-windows-amd64.exe`. Предыдущие версии не перезаписываются. Восстановлены архивные сборки v0.1.0, v0.1.1, v0.1.2 и v0.2.0 из соответствующих Git-тегов; прежний файл без номера версии оставлен для совместимости. `SHA256SUMS` содержит суммы всех сохранённых `.exe`. В GitHub Release прикладывается файл соответствующей версии.

## Освоение Эдема · v0.3.0

Существующая галактика автоматически дополняется планетами и регионами в той же `DB_SCHEMA`. Звёздные идентификаторы, координаты и гиперкоридоры не заменяются. Новые галактики получают преимущественно маломассивные звёзды; у уже сохранённых звёзд классы сохраняются. Перезапуск не меняет результаты разведки, остатки месторождений, корабли и рынки.

Регионы: **Кузни Сварога** (Орихалк), **Сады Гесперид** (Амброзия), **Пределы Айн Соф** (Азот алхимиков), **Мандала Акаништхи** (Ваджра), **Безмолвие Техом** (Агни). Регион — прежний рукав графа; последний охватывает изолированные системы. Имена отображаются на карте и в карточке корабля. Названия вдохновлены разными традициями; это игровая география, не утверждение об их исторической связи.

Каталог: Орихалк — металл из античной традиции; Ваджра — название минерала по индийскому символу алмаза/громового жезла; Азот алхимиков (Azoth, не химический азот) — реагент; Агни — игровое топливо, названное в честь ведийского божества огня; Амброзия и Манна — агроресурсы из греческой мифологии и библейского повествования. Происхождение названия доступно при наведении на ресурс. Физические свойства этих игровых материалов не выдаются за свойства реальных веществ.

У каждой звезды 3–7 планет с массой, примерной гравитацией, расстоянием в AU, классом атмосферы и равновесной температурой в K. Температура рассчитана приближённо из светимости и расстояния при нулевом альбедо и равномерном распределении полученной энергии; парниковый эффект не моделируется. Тип планеты и температурный диапазон влияют на доступные ресурсы; регион добавляет специализацию, где условия допускают её. Сбор агроресурсов и газов пока упрощён до общего действия извлечения: фермы, переработка и специальное оборудование появятся позже.

Игровой цикл:

1. Получите корабль «Пилигрим» в ED-0001: 60 единиц грузового пространства, бак на 40, стартовое топливо 30.
2. Исследуйте текущую систему за 10 CR. Повторная разведка бесплатна; до разведки планеты скрыты. Результаты принадлежат аккаунту.
3. Извлекайте по 3 единицы ресурса с планеты раз в 10 секунд. Совместный запас месторождения — 1000 единиц; он истощается и не восстанавливается автоматически. Место в трюме проверяется сервером.
4. Покупайте и продавайте ресурсы на локальном рынке. Цены зависят от региона, станции и дефицита; указанная цена фиксируется для одной партии. У станции конечные запасы и бюджет 5000 CR при первой инициализации. Пополнение товаров из воздуха отсутствует; новые товары поступают от игроков и ботов.
5. Купите Агни и заправьтесь: 1 единица даёт до 5 топлива, не выше ёмкости бака.
6. Введите номер системы или выберите звезду на карте. Перелёт требует существующего пути, 2 топлива и 5 секунд на переход. Выбор звезды заполняет поле назначения корабля; отправление требует отдельного нажатия.
7. Пока корабль в пути, разведка, добыча, заправка и торговля недоступны. Прибытие восстанавливается по сохранённому сроку при следующем запросе, в том числе после перезапуска службы.

Все игроки пока начинают в ED-0001; несвязанные рукава и изолированные звёзды остаются недоступными для этого стартового корабля. Между системами одного рукава есть различия цен. Рынок — станционный обмен с ограниченным кошельком, не биржа заявок между игроками. Боты пока торгуют на стартовой станции, не перевозят грузы между системами. Стартовые запасы станций создаются один раз. Разведка выводит плату из экономики; торговля переносит кредиты между кошельками. Старая учебная шахта ORE сохранена отдельно для совместимости и остаётся источником стартового дохода; экономика пока не является полностью замкнутой.

`GET/POST /api/expedition` возвращает состояние корабля и принимает `scan`, `mine`, `buy`, `sell`, `refuel`, `travel`. Требуется сессия. Операции транзакционные: блокируются игрок, корабль и затронутый рынок. Сервер проверяет путь, топливо, доступность месторождения, баланс, запасы, период добычи и вместимость. Карта мира кешируется в процессе; для ручных изменений её JSON в БД потребуется перезапуск службы.
