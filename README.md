# Cosmosimulator · 0.3.2

Лёгкая браузерная космическая экономическая песочница: Go + PostgreSQL, встроенный HTML/CSS/JavaScript. Один Windows x64 `.exe`, без npm и отдельного сервера интерфейса.

Планы разработки: [отчёт о составе 0.3.3](docs/roadmap/v0.3.3-report.md), [подробный план 0.3.3](docs/roadmap/v0.3.3.md), [отложенные идеи](docs/roadmap/deferred.md), [отклонённые идеи](docs/roadmap/rejected.md). [Реестр решений](docs/roadmap/README.md) сохраняет исходные номера всех 50 предложений. Это планы, а не описание уже выпущенных возможностей.

## Запуск в Windows

Нужна существующая база PostgreSQL 17 или совместимой версии. Создавать отдельную базу для игры не обязательно: `DB_SCHEMA` выбирает схему, по умолчанию `public`. Отсутствующая схема создаётся автоматически при наличии права `CREATE` на базу. Альтернатива — заранее создать схему в нужной базе:

```sql
-- Роль cosmos должна существовать; команда выполняется в вашей существующей базе.
CREATE SCHEMA cosmosimulator AUTHORIZATION cosmos;
```

Пользователь службы должен владеть игровой схемой или иметь `USAGE`, `CREATE` и нужные права на её таблицы и последовательности. Не используйте схему с чужими таблицами `users`, `ships`, `companies` и другими именами приложения.

PowerShell:

```powershell
$env:DATABASE_URL = 'postgres://cosmos:YOUR_URL_ENCODED_PASSWORD@127.0.0.1:5432/existing_database?sslmode=disable'
$env:DB_SCHEMA = 'cosmosimulator'
$env:HTTP_ADDR = '127.0.0.1:8080'
# Только для первоначального создания администратора:
$env:ADMIN_USERNAME = 'operator'
$env:ADMIN_PASSWORD = 'YOUR_UNIQUE_PASSWORD_AT_LEAST_12_BYTES'
.\downloads\cosmosimulator-v0.3.2-windows-amd64.exe
```

Откройте `http://localhost:8080`. Для остановки нажмите Ctrl+C. После создания администратора удалите переменные `ADMIN_USERNAME` и `ADMIN_PASSWORD`. Существующие пароли bootstrap не меняет, аккаунт игрока автоматически не повышает. `.env.example` — справочник: `.env` автоматически не читается.

`DB_SCHEMA` — одно точное имя, не список схем. Имена с пробелами/кавычками экранируются, длина ограничена 63 байтами. Системные схемы и специальное имя `$user` запрещены. Смена схемы не переносит данные. Настройка применяется ко всем соединениям пула, без автоматического поиска таблиц в `public`.

Для доступа извне настройте HTTPS reverse proxy, `PUBLIC_ORIGIN=https://your-domain`, `COOKIE_SECURE=true` и подходящий `HTTP_ADDR`. `sslmode=disable` предназначен для локальной БД; для удалённой используйте проверяемый TLS, например `sslmode=verify-full`. Не коммитьте строки подключения и пароли.

## Windows-служба и обновление

Файл поддерживает Service Control Manager. Проверьте консольный запуск, затем скопируйте выбранную версию из `downloads` в `C:\Cosmosimulator\cosmosimulator.exe`. В PowerShell администратора:

```powershell
sc.exe create Cosmosimulator binPath= 'C:\Cosmosimulator\cosmosimulator.exe' start= auto
New-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Services\Cosmosimulator' -Name Environment -PropertyType MultiString -Value @('DATABASE_URL=postgres://cosmos:YOUR_URL_ENCODED_PASSWORD@127.0.0.1:5432/existing_database?sslmode=disable','DB_SCHEMA=cosmosimulator','HTTP_ADDR=127.0.0.1:8080') -Force
sc.exe start Cosmosimulator
sc.exe query Cosmosimulator
```

Окружение службы отличается от окружения окна PowerShell. Ограничьте доступ к её настройкам, содержащим пароль БД. Перед обновлением остановите службу, сделайте резервную копию схемы и замените установленный `.exe` новой версией. Запускайте только одну версию сервера на одной схеме: старые версии не обрабатывают новые задания добычи. Миграции выполняются автоматически при старте с транзакцией и advisory lock. Прежняя карта, аккаунты, трюмы и кредиты сохраняются. Нативная Windows-служба поддержана кодом, но в облачной Linux-среде проверены кросс-компиляция и работа Linux-сервера, не реальный SCM.

## Интерфейс модулей

Слева находится сворачиваемая панель: карта, корабль, разведка и добыча, рынок и единая «Корпорация». Открытые модули отмечены подсветкой. В настройках доступны компактный режим и восстановление расположения окон. Главная страница содержит только сводку. Статус соединения — слева в футере.

Окна независимы: можно открыть несколько, перенести за заголовок, изменить размер за нижний правый угол, закрепить кнопкой ⌖ и закрыть кнопкой × или Escape. Закрепление запрещает перемещение и изменение размера. Положение, размеры, закрепление и состояние панели сохраняются в браузере. При недостаточном размере окно предлагает увеличить его вместо показа обрезанного интерфейса. Стрелки на выбранном заголовке перемещают незакреплённое окно.

Вверху находится профиль с векторной иконкой и никнеймом: из его меню открываются профиль игрока, настройки и журнал событий. Меню раскрывается с короткой анимацией; системное уменьшение анимаций учитывается. Уровень и опыт отображаются на главной странице, корпорация — цветным тегом. Кнопка ручного обновления убрана: работает автоматическое обновление и индикатор переподключения. Доступны русский и английский, выбор сохраняется в браузере. Подсказки с пунктирным подчёркиванием раскрывают смысл параметров при наведении или фокусе клавиатурой. `G` — спектральный класс, `M☉` — солнечная масса, `L☉` — солнечная светимость, `AU` — астрономическая единица, `K` — кельвины, `g` — земная сила тяжести.

Переводы хранятся в `internal/server/web/ru.json` и `en.json`, модуль — `i18n.js`. Для нового языка нужны словарь с теми же ключами, код в списке поддерживаемых языков и пункт выбора.

## Галактика и системы

Эдем содержит 1000 звёзд, 2916 двунаправленных гиперкоридоров, четыре связанных рукава по 245 систем и 20 изолированных звёзд. Пересечения линий не создают соединений. BFS ищет кратчайший путь по числу переходов. Галактика сохраняется в PostgreSQL; seed `20261026`. Существующие координаты, классы звёзд и коридоры при обновлениях не заменяются. Генератор принимает количество систем, но для существенно больших миров понадобится оптимизация квадратичного поиска соседей.

Нажатие на звезду переключает карту галактики на карту её системы. Также можно ввести номер системы и нажать «Открыть систему». Кнопка «К галактике» возвращает общий вид. Локальный вид показывает орбиты планет, астероидный пояс, ледяное поле в чётных системах и от одного до трёх портов в системах, номер которых не делится на 3. В ED-0001 и ED-0005 станция гарантирована. Нажатие ЛКМ/ПКМ на объект карты или его кнопку справа открывает контекстное меню: информация, приближение, орбита для планет, стыковка для портов. Информация — отдельное окно с крупным изображением, параметрами и квотами. Масштаб и перемещение работают и в локальной системе; есть фильтры объектов и кнопка показа всей системы. Орбиты поясов и станций масштабируются по квадратному корню светимости звезды: ледяное поле не располагается в зоне испарения только из-за фиксированного расстояния. Орбиты схематические, расстояния нормализованы для читаемости. До разведки видны орбитальные контакты и приблизительные физические свойства, но не месторождения.

У звезды 3–7 планет с массой, гравитацией, атмосферой и равновесной температурой. Температура приближена из светимости и расстояния при нулевом альбедо и равномерном распределении энергии, без парникового эффекта. Новые галактики получают преимущественно маломассивные звёзды; в сохранённом мире старые классы остаются. Карта кешируется сервером; ручное изменение её JSON в БД требует перезапуска.

Регионы и специализации:

- Кузни Сварога — Орихалк.
- Сады Гесперид — Амброзия.
- Пределы Айн Соф — Азот алхимиков.
- Мандала Акаништхи — Ваджра.
- Безмолвие Техом — Агни; этот регион охватывает изолированные системы.

Ресурсы используют культурные названия, не утверждения о реальных химических веществах: Орихалк — античный металл, Ваджра — индийский символ алмаза/громового жезла, Azoth — алхимический агент (не химический азот), Агни — игровая марка топлива в честь ведийского божества огня, Амброзия и Манна — агроресурсы из греческой мифологии и библейского повествования. Происхождение названия доступно в подсказке. Агроресурсы и газы пока собираются общим действием извлечения; фермы и специализированное оборудование не моделируются.

## Добыча, корабль и уровень

Все начинают в ED-0001 с кораблём «Пилигрим»: трюм 60, бак 40, топливо 30. Разведка текущей системы стоит 10 CR и даёт 10 XP; повторная бесплатна. Данные разведки принадлежат аккаунту.

Кнопка «Добыть 3» теперь запускает сохраняемое задание, а не немедленное начисление. Материал резервируется в месторождении, 3 места в трюме — под результат. Прогресс показывается в модуле добычи. На следующей фазе звёздной даты груз автоматически поступает в трюм, появляется уведомление и начисляется 5 XP. Новый цикл требует нового нажатия; бесконечная автоматическая добыча не включена. Пока цикл не завершён, перелёт запрещён. Добыча идёт партиями до 3 единиц; последняя партия может быть меньше. Новая система квот описана ниже. Для начала добычи нужно находиться у соответствующего объекта; орбита планеты или приближение к поясу допустимы. Отмена возвращает зарезервированную квоту только в исходный период.

Корабль перемещается только по существующим путям: 2 топлива и 5 секунд на переход. Во время перелёта торговля, разведка и добыча недоступны. 1 Агни в трюме восстанавливает до 5 топлива. Срок прибытия сохраняется; прибытие восстанавливается запросом, в том числе после перезапуска. Несвязанные рукава пока недоступны стартовому кораблю.

Уровень принадлежит игроку, отображается на главной странице и повышается вручную: требуются `100 × текущий уровень` XP и столько же CR, которые расходуются. Максимум 100. Уровень пока не даёт скрытых бонусов к кораблю или добыче.

Учебное производство ORE сохранено в модуле добычи отдельно от планетных ресурсов: 1 ORE на игрока за тик и продажа по 5 CR. Оно связано с профилем и служит начальным источником дохода; это не стационарная шахта в фиктивном Kepler Belt. Интерфейс показывает текущую систему. Экономика поэтому пока не является полностью замкнутой.

## Рынок и бронирование

Локальный рынок доступен только после стыковки с портом. Порты одной системы пока используют общий склад и рынок. Покупка сразу поступает в трюм. Цены зависят от региона, станции и запаса; каждая партия имеет фиксированную цену сделки. Станция стартует с конечным запасом и 5000 CR. Три бота раз в 3 тика торгуют на стартовой станции, расходуя свой груз и деньги; старой бесконечной выручки нет.

Глобальный рынок показывает станции и предварительную стоимость выбранного ресурса. Бронирование списывает кредиты в escrow и убирает товар из доступного запаса продавца. До получения груз остаётся на станции, не занимает трюм и не телепортируется. Для получения требуется пристыковаться к любому порту указанной системы и иметь свободный трюм с учётом незавершённой добычи. Получение переводит оплату станции и выдаёт груз ровно один раз. Отмена возвращает всю оплату и товар в запас. Чужую бронь получить или отменить нельзя. Не более 100 активных броней на игрока; UI предупреждает об отсутствии пути к станции. Множество кораблей и автономные доставки пока отсутствуют.

## Корпорация

Новый и мигрированный игрок становится участником общей «Академии Эдема» (`EDM`). Аккаунт больше не считается отдельной компанией. Можно выйти, вступить в существующую организацию или создать свою: полное имя 3–60 символов, уникальный код из 3–4 букв/цифр, цвет и флаг из набора символов. Членство одно; перед сменой нужно выйти. Владелец пока обязан оставаться в своей компании: управление передачей владения не реализовано.

Единый модуль «Корпорация» содержит фильтры: все организации, регион и текущая система, а также создание/вступление. Отдельная иерархия холдингов, общие кошельки и приглашения не реализованы; вступление открыто. Пользовательские названия не переводятся, название стартовой организации локализуется.

## Администратор

Роли `player` и `admin` проверяются сервером. В верхнем меню администратора:

- «Пропустить тик» принудительно выполняет ровно один мировой тик, завершает положенные задания и сдвигает оставшееся время перелётов на длительность одного настроенного цикла. Меню после нажатия остаётся открытым. Автоматический тик сразу следом не дублируется.
- «Пользователи» показывает максимум 10 аккаунтов на страницу с серверным поиском по никнейму или ID. «Редактировать» открывает отдельное окно пользователя: имя, роль, кредиты, уровень, XP и необязательная смена пароля. Пустой пароль сохраняет прежний. Смена роли/пароля завершает сессии аккаунта. Ботам нельзя менять идентификацию. Нельзя понизить себя или последнего администратора.

Естественный цикл по умолчанию — раз в 10 секунд; его длительность меняется в настройках игрового процесса. Добыча зависит от тиков работающего сервера; перелёт — от сохранённого срока. Простой не превращается в бесконечное число производственных тиков.

## Корабль, положение и трюм · 0.3.2

На карте галактики отображаются собственные корабли; перелёт рисуется вдоль сохранённого пути гиперкоридоров. API `/api/fleet` возвращает массив, рендерер поддерживает несколько маркеров и группировку в одной системе. В текущей игре по-прежнему один «Пилигрим» на аккаунт; создание дополнительных кораблей ещё не реализовано.

В локальной системе есть точное игровое положение: объект и режим `approach`, `orbit` или `docked`. Контекстное меню планеты предлагает приближение и орбиту, порта — стыковку. Манёвр занимает 5 реальных секунд и расходует 1 топлива. Во время манёвра остальные действия недоступны. По завершении режим и объект сохраняются; маркер корабля следует движению, а на орбите отображается вращением вокруг объекта. После гиперперехода корабль находится у точки входа, а не автоматически в порту. Навигация и анимации схематические, без интегрирования реальной небесной механики.

Планеты окрашены по типу: ледяные синие, каменистые серые, садовые зелёно-голубые, горячие вулканические красно-оранжевые. Газовые гиганты крупнее и имеют полосы. Пояса показаны камнями/кристаллами, порты — отдельным значком станции. Садовый мир — игровая классификация условий, не гарантия пригодной для дыхания атмосферы.

В окне корабля встроена SVG-схема «Пилигрима». Кнопка «Трюм» раскрывает отдельную панель: справа в широком окне, ниже на узком экране. Груз показан плитками с количеством и кодом: ORI, VJR, AZT, AGN, AMB, MNA, FE, C, H2O, SI. Наведение/фокус показывает полное описание, источники, редкость и теги использования. ЛКМ/ПКМ открывает действия: информация, заправка для Агни, продажа выбранного количества/всего груза после стыковки, рынок. Есть фильтры категории/редкости, сортировка и индикатор занятого/зарезервированного места.

## Ресурсы и восстанавливаемые квоты

Добавлены обычные железо, углерод, водяной лёд и кремний. Специальные материалы сохраняют мифологические названия. Распределение детерминировано по системе и объекту: железо встречается часто, но не везде; Орихалк, Ваджра и Амброзия редки. В системах и на объектах разные наборы. Рынки могут иметь импортные стартовые запасы, поэтому наличие товара на станции не доказывает местную добычу.

Общий бюджет каждого добывающего объекта — **5000 единиц на всех игроков и все его ресурсы**. У каждого редкого ресурса на объекте дополнительный предел **300–600**, входящий в общий бюджет. Лимит конкретного редкого месторождения стабильно вычисляется из идентификаторов. По умолчанию восстановление раз в **5 реальных часов**, независимо от звёздной даты, ручных циклов и простоя сервера.

Квота списывается при начале задания и резервируется атомарно. Отмена в том же периоде возвращает её. Смена периода не отменяет уже зарезервированный груз и не выдаёт его дважды; отмена старого задания не увеличивает новую квоту. Остаток и время восстановления видны в разведке и карточке объекта. Пропущенные периоды вычисляются при обращении к объекту, без фонового перебора всей галактики.

«Панель администратора → Игровой процесс» показывает период в часах (по умолчанию 5), общий лимит, диапазон редких ресурсов, длительность цикла и скорость даты. Изменения действуют для новых периодов; действующие окна сохраняют прежние значения. Отдельная подтверждаемая команда применяет значения формы и немедленно восстанавливает квоты. Она не сбрасывает трюмы, деньги и рыночные запасы.

Старые статические `deposits` сохранены для совместимости, но новая добыча использует `resource_quotas`. При первом обновлении до 0.3.2 геология планет обновляется до нового распределения; координаты/ID, гиперкоридоры, исследования, уже добытый груз, брони и текущие задания сохраняются. Старая запись перелёта дополняется маршрутом и временем отправления без изменения ETA.

## Хронология и журналы

На главной странице вместо номера такта отображается **Хронология Эдема**, например `ЭД 0001·042·318`: год, день, импульс. 360 дней в году, 1000 импульсов в дне. Настраиваются реальные секунды между циклами (1–3600, по умолчанию 10) и импульсы даты на цикл (1–10000, по умолчанию 1). Скорость даты сама по себе не меняет время перелёта и восстановление квот. При ручном продвижении сдвигаются оба конца временной шкалы перелёта, поэтому маркер сохраняет правильное положение вдоль маршрута.

Личный журнал содержит разведку, добычу, манёвры, прибытия, торговлю, бронирования и повышение уровня. Настройки игрового процесса и редактирование пользователей записываются в административный журнал с автором; пароли и хеши в него не попадают. Журнал показывает последние записи, без обещания полноценной системы финансового аудита.

## Разработка, проверки и сборки

Go 1.26+, PostgreSQL. Из корня:

```sh
go mod download
go vet ./...
go test ./...
DB_SCHEMA=cosmosimulator DATABASE_URL='postgres://cosmos:password@127.0.0.1:5432/existing_database?sslmode=disable' go run ./cmd/cosmosimulator
```

Для интеграции нужна отдельная одноразовая база с именем, заканчивающимся на `_test`, и права создания схем. Тесты создают/удаляют временные схемы; никогда не указывайте рабочую игровую базу:

```sh
TEST_DATABASE_URL='postgres://cosmos:password@127.0.0.1:5432/cosmosimulator_test?sslmode=disable' go test -race -count=1 -v ./...
```

Без `TEST_DATABASE_URL` интеграционные тесты пропускаются. Проверяются авторизация, роли, миграции, изоляция схем, карта и пути, добыча по тикам, торговля и переполнение трюма, бронь и параллельное получение, компании, ручной тик, редактирование аккаунтов, опыт и повышение уровня. Тесты 0.3.2 дополнительно проверяют совместную квоту и последнюю неполную партию, отмену между периодами, редкие лимиты, настройки/звёздную дату, положение/орбиту/стыковку корабля, миграцию старого перелёта, страницы пользователей и разнообразие ресурсов.

Linux → Windows x64:

```sh
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -trimpath -ldflags='-s -w' -o downloads/cosmosimulator-v0.3.2-windows-amd64.exe ./cmd/cosmosimulator
sha256sum downloads/*.exe > downloads/SHA256SUMS
```

Каждое обновление получает новое имя файла с версией; старые `.exe` не перезаписываются. Проверенные исходники и сборка коммитятся вместе; тег `vX.Y.Z` запускает GitHub Actions, который прикладывает соответствующий `.exe`, описание из `release-notes/vX.Y.Z.md` и контрольные суммы. Новую версию не следует собирать поверх уже опубликованного файла.

Основные API: `/api/health`, `/api/state`, `/api/galaxy`, `/api/route`, `/api/system?id=N`, `/api/expedition`, `/api/profile`, `/api/profile/upgrade`, `/api/companies`, `/api/market/global`, `/api/admin/users`, `/api/admin/user`, `/api/admin/tick`, `/api/fleet`, `/api/gameplay`, `/api/admin/gameplay`, `/api/events`, `/api/admin/log`. Изменения выполняются POST JSON с проверкой Origin; кроме health/static, нужна сессия. Пароли bcrypt, случайные сессионные токены хранятся в БД в виде хеша, cookies HttpOnly. `/api/state.companies` — старое совместимое поле списка игроков; актуальные организации выдаёт `/api/companies`.

Это ранняя версия: перед публичной MMO ещё нужны восстановление доступа, резервное копирование, защита от массовых регистраций и эксплуатационная настройка.
